# 解题方法论 · 四步思考法

> 拿到一道题后,从"看不懂"到"秒杀"的标准化流程。

---

## 核心思想

任何 LeetCode 题都可以套用这个框架:

```
Step 1: 读懂题意 → 把文字翻译成"输入/输出/约束"
Step 2: 建模 → 把问题抽象成"已知的数据结构 + 目标操作"
Step 3: 选型 → 选择"数据结构 + 算法模板"
Step 4: 编码 → 套模板 + 处理边界
```

---

## Step 1:读懂题意

**目标**:在纸上写出三个东西:

```
输入: [类型]   例如: 整数数组 nums,长度 n
输出: [类型]   例如: 满足条件的子数组个数
约束: n 的范围 (1 ≤ n ≤ 10^5?)
     元素范围
     时间要求?
```

**常见陷阱**:
- 看漏"非空"、"严格递增"、"至多一次操作"
- 把"子序列"和"子数组"混用
- 把"路径"和"任意节点出发"搞混

---

## Step 2:建模(把问题抽象)

**关键提问**:
- 这是在 **数组/链表/树/图** 上做什么操作?
- 操作是"查询"、"修改"还是"构造"?
- 多次查询还是单次?

**抽象工具**:
1. **不变量(invariant)**:求解过程中永远为真的性质
2. **单调性**:数组是否有序?函数是否单调?
3. **最优子结构**:大问题的最优解能否由子问题的最优解推出?

**练习**:看到"区间求和"立刻想到前缀和;看到"第 k 大"立刻想到堆。

---

## Step 3:选型(算法决策树)

按数据规模反推:

| n 范围 | 推荐复杂度 | 可用算法 |
|--------|----------|---------|
| n ≤ 20 | O(n!) O(2^n) | 暴力、回溯、状压 DP |
| n ≤ 100 | O(n^3) | Floyd、区间 DP |
| n ≤ 1000 | O(n^2) | 简单 DP、双重循环 |
| n ≤ 10^5 | O(n log n) | 排序、二分、树状数组 |
| n ≤ 10^6 | O(n) | 滑动窗口、双指针、哈希 |
| n ≤ 10^7 | O(n / 64) | 位运算压位 |

**核心:由约束倒推解法**。

---

## Step 4:编码(模板复用)

每个模式都有标准模板,见 `practice/templates.md`。

**编码 checklist**:
- [ ] 边界:n=0,n=1,空数组,空树,空字符串
- [ ] 越界:中点 mid,left+right 是否溢出
- [ ] 初始化:容器大小、初始值
- [ ] 返回:空集合、单元素、全元素

## 常见误区

1. **不要死磕** — 30 分钟没思路直接看题解,学习模式
2. **不要背代码** — 背模板、理解本质
3. **不要只刷 Easy** — Medium 才是主流
4. **不要忘记复习** — 1/3/7/21 天复习曲线
5. **不要抄答案** — 看完思路必须自己写一遍
