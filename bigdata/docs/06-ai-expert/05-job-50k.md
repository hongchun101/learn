## 3. Snowflake / StarRocks-style 案例项目样板

### 3.1 项目样板一:**电商实时数仓 0→1**(对标 Snowflake Stream + Iceberg)

#### 项目描述
为某电商平台搭建**PB 级实时 + 离线一体化数仓**,支撑 GMV、转化、用户画像、推荐等 200+ 核心指标。

#### 技术栈
```
数据采集:Canal / Flink CDC → Kafka (100+ topics)
实时计算:Flink 1.18 + Flink SQL (200+ 作业)
湖格式:Apache Iceberg 1.4 (ACID / 隐藏分区 / 时间旅行)
OLAP:Doris 2.x (秒级响应 / 物化视图)
调度:Apache DolphinScheduler 3.x
治理:Apache Gravitino (统一元数据)
监控:Prometheus + Grafana + Loki
可观测:OpenTelemetry
```

#### 关键技术决策
1. **为什么选 Iceberg?** 支持 ACID + 隐藏分区 + schema 演进 + 多引擎(Spark/Flink/Trino);
2. **为什么选 Flink CDC?** 替代 Canal,支持整库同步 + DDL 变更;
3. **为什么选 Doris?** MPP 架构 + 向量化 + 实时 upsert,比 StarRocks 更适合明细查询;
4. **为什么用 Gravitino?** 统一 Hive / Iceberg / Doris / Kafka 元数据,跨引擎查询。

#### 量化结果
| 指标 | Before | After | 提升 |
| --- | --- | --- | --- |
| 数据延迟 | T+1(8h) | 秒级 | **28800×** |
| 存储成本 | ¥30w/月 | ¥10w/月 | **-66%** |
| 查询延迟 | 30s | 1s | **30×** |
| 故障恢复 | 4h | 15min | **16×** |
| 团队效率 | 10 人 | 5 人 | **+100%** |

#### 你的角色
- **Owner**:从 0 到 1 设计架构,主导落地;
- **推动跨团队**:协调业务 / 后端 / 数据 / 算法 4 个团队;
- **代码贡献**:写 50% 核心 Flink 作业 + 100% Doris 表设计;
- **文档输出**:写 20+ 技术 wiki + 5 次内部分享。

### 3.2 项目样板二:**湖仓一体成本治理**(对标 Snowflake Auto-suspend)

#### 项目描述
某公司大数据集群 ¥500w/月,通过存算分离 + Spot + 冷热分层降到 ¥150w/月。

#### 技术栈
- JuiceFS(替代 HDFS)
- Apache Celeborn(替代本地 shuffle)
- Karpenter(替代 Cluster Autoscaler)
- OSS / S3 生命周期
- 自研内部计费平台

#### 关键决策
1. **JuiceFS 选型**:POSIX 兼容 + 元数据用 TiKV,延迟 < 1ms;
2. **Spot 覆盖率**:离线 70% 任务切 Spot,中断恢复用 Spark maxFailures=4;
3. **冷数据归档**:30 天前数据自动转 OSS Archive / S3 Glacier;
4. **成本埋点**:Spark Listener + Flink Meter 写到 Kafka,BI 看板分团队。

#### 量化结果
| 优化项 | 节省/月 |
| --- | --- |
| Spot 实例 | ¥80w |
| 存算分离 | ¥60w |
| 冷数据归档 | ¥40w |
| 压缩 ZSTD | ¥25w |
| 周末关机 | ¥40w |
| GPU 共享 | ¥30w |
| 其他 | ¥65w |
| **合计** | **¥340w** |

### 3.3 项目样板三:**AI 数据流水线**(LLM 预训练数据)

#### 项目描述
为某大模型团队搭建 **TB 级预训练数据流水线**,支持 MinHash 去重 + 质量打分 + 毒性过滤。

#### 技术栈
- Apache Spark + Ray(分布式清洗)
- datatrove / datasketch(去重)
- Hugging Face tokenizers(分词)
- Apache Iceberg(数据入湖)
- bge-m3 / Qwen3-Embedding(语义评分)
- 自研评测平台

#### 关键决策
1. **MinHash LSH 调参**:`num_perm=128, b=4, r=32`,1 亿文档查重 P99 < 50ms;
2. **质量打分**:KenLM Perplexity + Gopher 规则 + Embedding 相似度;
3. **PII 脱敏**:Microsoft Presidio + 正则双重;
4. **评测闭环**:Langfuse + 人工评测 500 条/天。

#### 量化结果
- 处理数据:**10TB/月** → 训练可用 5TB;
- 去重率:35%(高质量);
- 毒性过滤:**99.5%**;
- 模型评测:BLEU +3.2,人工评测 +5.4。

### 3.4 项目样板四:**Doris 替代 StarRocks**(实际降本)

#### 项目描述
某公司 OLAP 选型 Doris vs StarRocks,经压测 Doris 完全胜任,**降本 40%**。

#### 压测对比
| 场景 | Doris 2.x | StarRocks 3.x |
| --- | --- | --- |
| SSB 100G | 0.8s | 0.6s |
| TPC-H 1T | 5s | 4s |
| 单副本写吞吐 | 100MB/s | 120MB/s |
| 社区活跃度 | ★★★★★ | ★★★★ |
| License | Apache 2.0 | Elastic License |

#### 决策
- 数据量 < 10PB / 查询并发 < 1000 → Doris 更划算;
- 极致性能 / 大规模 → StarRocks。

## 4. 项目经验包装方法(★ STAR + 量化)

### 4.1 STAR 模型

```
S (Situation)    : 项目背景 / 挑战
T (Task)         : 你的具体任务
A (Action)       : 你做了什么(技术决策 + 关键动作)
R (Result)       : 量化结果(指标提升 / 成本降低)
```

### 4.2 项目包装示例

#### ❌ 错误写法(普通候选人)

> 负责公司大数据平台建设,使用 Spark / Flink / Kafka 等技术。

#### ✅ 正确写法(50K 候选人)

> **项目名称**:电商实时数仓 0→1 落地(2024.06–2025.12)
>
> **背景(S)**:公司原有离线 T+1 数仓延迟 8h,无法支撑实时推荐 / 风控;Kafka 集群 ¥30w/月,Spark 集群 ¥80w/月,存储 ¥40w/月,总 ¥150w/月,**成本高 + 延迟大**。
>
> **任务(T)**:Owner,设计实时数仓架构 + 主导跨 4 团队落地(数据 / 业务 / 后端 / 算法)+ 输出统一规范。
>
> **行动(A)**:
> 1. **技术选型**:Iceberg(湖格式)+ Flink CDC(整库同步)+ Doris(OLAP),3 周完成 POC;
> 2. **架构设计**:Kafka → Flink SQL → Iceberg → Doris,**端到端秒级**;
> 3. **性能优化**:AQE + Salting 解决数据倾斜,任务从 4h 缩到 30min;
> 4. **治理落地**:Gravitino 统一元数据 + Iceberg 血缘 + Doris 数据质量 SLA;
> 5. **成本治理**:JuiceFS 存算分离 + Spot 实例 + 冷数据归档,**降本 ¥80w/月**。
>
> **结果(R)**:
> - **延迟**:T+1 → 秒级,提升 **28800×**;
> - **存储**:¥40w → ¥12w/月,**降本 70%**;
> - **查询**:P99 30s → 1s;
> - **故障恢复**:4h → 15min;
> - **团队**:从 10 人缩到 5 人,**人效 +100%**;
> - **业务影响**:支撑 200+ 核心指标,推荐转化率 +5%,GMV +¥200w/月。

### 4.3 简历"五要点"

1. **数字 + 单位**:不是"提速"而是"从 4h 到 30min";
2. **技术栈具体到版本**:Spark 3.5、Flink 1.18、Iceberg 1.4;
3. **你的角色**:不是"参与",而是"Owner / 主导";
4. **量化收益**:成本节省 / 延迟降低 / 业务增长;
5. **项目复杂度**:PB 级 / 跨 4 团队 / 200+ 指标。

- **先 offer 后谈薪**,不要在流程中过早暴露期望;
- **报范围而非数字**:"60–80K",猎头一般给中位数;
- **同 level 横比**:P7(阿里)≈ 3-1(字节)≈ L7(美团),base 应相近;
- **签字费 / 股票**:大厂可谈,5–10w 签字费 + 20–50w 股票;
- **期权的隐性价值**:上市公司看股价,未上市看估值涨幅。

## 8. 专家面试题(50K 真实高频)

1. **请介绍你最复杂的项目,技术决策点是什么?**
   *用 STAR,突出架构选型、量化收益、跨团队协作;忌"我做了什么什么",要"我决定用什么 + 为什么"。*

2. **Iceberg vs Hudi vs Paimon,你怎么选?**
   *Iceberg 通用 / Hudi upsert 强 / Paimon 流式;看团队熟悉度 + 业务场景。*

3. **团队 10 人,你怎么分工?**
   *按能力分组 + 模块化 + Code Review + OKR;忌"我一个人说了算"。*

4. **老板要你 3 个月做一个实时数仓,你怎么做?**
   *调研 + POC + 选型 + PoC + 试点 + 推广;忌上来就开干。*

5. **跨团队项目怎么推动?**
   *定 owner + 排期 + 同步会 + 风险预警;忌"扯皮文化"。*

6. **Spark 调优和 Flink 调优的本质区别?**
   *Spark 批为主,关注 shuffle / 数据倾斜;Flink 流为主,关注反压 / 状态。*

7. **你最擅长什么?最不擅长什么?**
   *说真话 + 学习中;忌"什么都会"。*

8. **你怎么看待加班?**
   *效率 > 加班;不接受长期 996,但接受关键期冲刺。*

9. **5 年后你想做什么?**
   *技术专家 / 架构师 / Tech Lead;忌"管理者"(会被认为想脱离技术)。*

10. **你有什么问题问我?**
    *问团队当前痛点 / 项目规划 / 技术栈;忌"薪资福利"。*

## 9. 生产经验

1. **简历必须 STAR + 量化**。
2. **GitHub 是简历的延续**:1 个 1k+ star 项目 > 10 个半成品。
3. **技术 blog 是被发现的最佳方式**:InfoQ / 掘金 / 个人站,持续输出。
4. **内推成功率 3–5× 公开投递**:LinkedIn / 脉脉 / 朋友。
5. **谈薪不要 first move**:让猎头先报。
6. **offer 比较不要只比 base**:总包(股票 / 签字费)+ 业务 + 团队 + 晋升。
7. **面试官在意"思考过程",不在"标准答案"**。
8. **不会的题说不会 + 怎么学**:诚实 > 编造。
9. **离职原因避免负面**:平台限制 / 技术深度 / 业务转型。
10. **50K 不只是技术,也是商业 Sense + 沟通 + 影响力**。
