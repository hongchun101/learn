# 第 00 章 学习方法论与教程结构

> 工程师成长三阶:能写、能调、能讲。本教程目标 18 个月把读者推到 50K/月数据专家位,前提是你用对了方法。

---

## 一、为什么大多数学习路径失败

新人学大数据最常见的死循环:

```
读文档 -> 跑 Demo -> 报错 -> 复制粘贴 -> 通过 -> 遗忘 -> 再读文档
   ^                                                  |
   |__________________________________________________|
```

本质是**没有构建可迁移的心智模型**。Spark 调参背下来 30 个配置项,换个集群照样不会;HBase 调优背 10 个参数,业务换了又抓瞎。

正确姿势是 **三层知识栈**:

| 层级 | 内涵 | 例子 |
|------|------|------|
| 原理层 (Why) | 机制为何如此设计 | LSM-Tree 为什么适合写多读少、B+Tree 为什么适合范围扫 |
| 接口层 (What) | 暴露什么 API/配置 | Spark 的 `spark.sql.shuffle.partitions` |
| 战术层 (How) | 现场怎么用 | 磁盘满时怎么快速止血、GC 抖动怎么定位 |

只记战术层,3 个月就忘光;只啃原理层,产出太慢。本教程每个章节都按"原理 → 接口 → 战术"三段式写。

## 三、费曼学习法 + 主动回忆(操作手册)

不要逐字读文档。每读完一小节,做以下 5 步,耗时 15-30 分钟:

```
1. 合上文档,白板写出本节核心机制(画图)
2. 给自己讲一遍,假设对面是实习生
3. 提 3 个"如果...会怎样"的反事实问题
4. 写 1 个能跑通的最小复现例子
5. 记 1 条"生产里见过的坑"
```

判断你是否真的学会:

| 现象 | 含义 |
|------|------|
| 能给别人讲 5 分钟不卡壳 | 真懂 |
| 能指出文档里没说清的边界条件 | 真懂 |
| 离开 IDE 口述出关键 API | 真懂 |
| 只记得关键词讲不出机制 | 假懂,需要重读 |

## 五、笔记系统的具体做法(可直接抄)

推荐目录结构,放进任意 Git 仓库:

```
notes/
├── daily/             每日工作日志,YYYY-MM-DD.md
├── topics/            主题笔记,如 spark-tuning.md
│   └── spark-tuning.md  [摘要 + 原理 + 案例 + 引用]
├── questions/         面试题,按公司/岗位分
│   └── bytedance-senior.md
└── references/        论文链接、官方文档摘录
```

**一个主题笔记的标准模板**:

```markdown
# Spark Shuffle 调优

## 一句话原理
Shuffle 是把 Map 端数据按 partition key 重分布到 Reduce 端,
网络 IO + 序列化 + 排序 三件事决定吞吐。

## 关键配置(接口层)
| 配置 | 默认 | 推荐 | 影响 |
|------|------|------|------|
| spark.sql.shuffle.partitions | 200 | 任务并发 * 2~3 | 单 task 数据量 |
| spark.shuffle.file.buffer | 32K | 64K | 写盘缓冲 |

## 生产案例
2024-10 某 ETL 任务 shuffle stage 慢,根因:
partitions=200 但数据 1.2TB → 单 task 6GB 撑爆内存
调为 600 后从 47 分钟降到 12 分钟。

## 引用
- Spark 官方 tuning guide
- 美团技术博客《Spark 性能优化指南》
```

## 六、时间分配(给在职学习者)

每周 14 小时可持续方案:

| 时段 | 时长 | 内容 |
|------|------|------|
| 工作日早 | 30 min × 3 | 读原理文档、做笔记 |
| 工作日晚 | 60 min × 2 | 写代码、跑实验 |
| 周末上午 | 120 min × 1 | 实战任务、调优实验 |
| 周末下午 | 120 min × 1 | 复盘、写博客、刷题 |

**雷区**:刷算法题超过 30%/总学习时间。50K 月薪的数据岗,LeetCode Medium 80 题足够,远不需要 Hard 500 题。把时间花在读源码、写复现、做分享上,回报率高 10 倍。

## 实战任务

1. 在 `~/notes/topics/` 下新建 `01-java-concurrency.md`,用本文档"主题笔记模板"写一份你自己的 Java 并发笔记骨架(先空着,等下一章填)。

5. 把本节"三层知识栈"画成你自己的 ASCII 图,贴到笔记里。

## 专家面试题

1. **介绍一个你最近深入研究的技术,以及怎么研究的?**
   要点:用费曼学习法讲 3 分钟;强调原理层 + 生产案例 + 量化收益。

2. **你怎么判断自己真的"懂"了一个技术,而不是"看过"?**
   要点:能脱离文档讲;能做反事实推理;能写最小复现;能在生产里独立定位问题。

3. **在职学习时间有限,你怎么分配?**
   要点:工作日碎片时间读原理(高密度),周末大块时间做实验(高产出);比例 7:3 而非 5:5。

4. **你做的笔记系统是怎么设计的?为什么?**
   要点:可 grep(纯文本)、可版本控制(Git)、可双链(Obsidian);拒绝 Word/PDF/Notion 富文本。

5. **你最近读了什么源码?讲一段你印象最深的细节。**
   要点:不要泛泛而谈,挑一个具体函数/类,讲清输入输出和边界条件,例如 `org.apache.spark.util.collection.ExternalSorter`。

## 生产经验

- **别用 Notion 做技术笔记**:API 改版、数据迁移、无法本地 grep,这三条任意一条都能要命。工程师的笔记必须活在 Git 仓库里,Markdown + 双链是 2026 年事实标准。
- **笔记不是抄书**:每条配置项必须配一个你见过的生产案例,没有就标 `[待补]`,半年后回看就清楚哪些是真懂。
- **博客 > 笔记**:把核心笔记整理成博客发出去,被动求职信。50K 候选人里 80% 没技术博客,这就是你和他们的差距。
