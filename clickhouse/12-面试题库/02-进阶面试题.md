# 12-面试题库 续：进阶面试题

## 12.6 进阶面试题（111-160）

### Q111：ClickHouse 的向量化执行原理？

**答**：
- 传统 Volcano 模型：每行调用一次函数
- ClickHouse 向量化：每次处理一个 Block（默认 65536 行）
- 优势：CPU 缓存友好、利用 SIMD 指令、减少虚函数调用
- 实现：`Block` + `Chunk` + 各种算子

### Q112：ClickHouse 的多主复制？

**答**：
- ReplicatedMergeTree 支持多主写入
- 通过 ZooKeeper 协调
- 冲突解决：版本号（最后写入获胜）
- 不推荐：会增加协调开销

### Q113：ClickHouse 的副本一致性级别？

**答**：
- 默认：最终一致
- 强一致：需要等所有副本确认（性能下降 5-10 倍）
- 实际：业务层保证幂等

### Q114：ClickHouse 的 ZooKeeper 故障影响？

**答**：
- 副本无法注册
- 复制任务暂停
- 已有数据可读
- 恢复后自动同步

### Q115：ClickHouse 的冷启动慢怎么办？

**答**：
1. 增加 mark_cache_size
2. 启用 mark_cache_prefer_parallel_merges
3. 预热关键表
4. 减少表数量

### Q117：ClickHouse 的数据倾斜问题？

**答**：
- 表现：部分节点 CPU/磁盘远高于其他
- 原因：分片键选择不当
- 解决：
  1. 选用高基数列做分片键
  2. 加盐（`sharding_key = 'cityHash64(user_id, rand() % 16)'`）
  3. 多级聚合

### Q119：ClickHouse 的异步插入原理？

```sql
SET async_insert = 1;
SET wait_for_async_insert = 1;
SET async_insert_max_data_size = 1000000;
SET async_insert_busy_timeout_ms = 200;
```

- 客户端发送 INSERT
- 服务端缓冲到内存
- 达到阈值（时间或大小）后批量刷盘
- 优势：高并发小写入性能提升 100 倍

### Q128：ClickHouse 的连接池管理？
