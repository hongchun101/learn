# 07-高性能架构 续：数据复制与扩容

## 7.7 数据复制机制深入

### 7.7.1 ReplicatedMergeTree 工作原理

```
写入流程：
  Client → Local Replica (Leader)
            ↓
  1. 写入本地 Part
  2. 记录到 ZooKeeper log
            ↓
  3. 其他副本 Watcher 触发
            ↓
  4. 拉取 Part 数据
            ↓
  5. 写入本地 Part
            ↓
  6. 确认到 ZK
```

### 7.7.2 ZooKeeper 数据结构

```
/clickhouse/tables/
  ├── {shard}/
  │   ├── table_name/
  │   │   ├── metadata          # 表结构
  │   │   ├── columns           # 列信息
  │   │   ├── replicas/
  │   │   │   ├── {replica_name}/
  │   │   │   │   ├── is_active
  │   │   │   │   ├── log_pointer
  │   │   │   │   └── queue/
  │   │   │   │       ├── block-0000000001
  │   │   │   │       └── ...
  │   │   ├── blocks/
  │   │   │   └── ...
  │   │   ├── leader_election-0000000001
```

### 7.7.3 副本配置示例

```xml
<!-- 主副本配置 -->
<macros>
    <shard>01</shard>
    <replica>node1</replica>
</macros>

<!-- 从副本配置 -->
<macros>
    <shard>01</shard>
    <replica>node2</replica>
</macros>
```

```sql
-- 创建副本表（每个节点执行）
CREATE TABLE events_replicated
(
    event_id UInt64,
    event_time DateTime,
    user_id UInt64,
    amount Decimal(10, 2)
) ENGINE = ReplicatedMergeTree(
    '/clickhouse/tables/{shard}/events',  -- ZK 路径
    '{replica}'                            -- 副本名
)
PARTITION BY toYYYYMM(event_time)
ORDER BY (user_id, event_time);
```

### 7.7.4 副本监控

```sql
-- 1. 复制状态
SELECT
    database,
    table,
    replica_name,
    is_readonly,
    is_session_expired,
    future_parts,
    parts_to_check,
    zookeeper_path,
    -- 延迟指标
    absolute_delay,
    total_replicas,
    active_replicas
FROM system.replicas
WHERE database = currentDatabase()
ORDER BY absolute_delay DESC;

-- 2. 复制队列
SELECT
    database,
    table,
    replica_name,
    position,
    node_name,
    type,
    source_replica,
    parts_to_merge,
    is_currently_executing,
    last_exception
FROM system.replication_queue
ORDER BY last_exception_time DESC
LIMIT 20;

-- 3. 副本数据一致性检查
SYSTEM SYNC REPLICA events_replicated;
```

## 7.8 跨集群复制

### 7.8.1 异步复制（推荐）

```sql
-- 1. 在目标集群创建表
CREATE TABLE events_replicated_target
(
    event_id UInt64,
    event_time DateTime,
    user_id UInt64,
    amount Decimal(10, 2)
) ENGINE = ReplicatedMergeTree(
    '/clickhouse/tables/{shard}/events',
    '{replica}'
)
PARTITION BY toYYYYMM(event_time)
ORDER BY (user_id, event_time);

-- 2. 创建分布式表
CREATE TABLE events_distributed_target
AS events_replicated_target
ENGINE = Distributed(
    'target_cluster', 'db', 'events_replicated_target', cityHash64(user_id)
);

-- 3. 在源集群创建远端表函数管道
CREATE TABLE events_replicator
(
    event_id UInt64,
    event_time DateTime,
    user_id UInt64,
    amount Decimal(10, 2)
) ENGINE = Distributed('source_cluster', 'db', 'events_source');

-- 4. 定时复制
INSERT INTO events_distributed_target
SELECT * FROM events_replicator
WHERE event_time >= now() - INTERVAL 1 HOUR;
```

### 7.8.2 ClickHouse Copier（官方工具）

```bash
# 1. 安装（已包含在 clickhouse-client 中）

# 2. 创建任务配置
cat > /etc/clickhouse-copier/task.xml <<EOF
<yandex>
    <remote_servers>
        <source_cluster>
            <shard>
                <internal_replication>true</internal_replication>
                <replica>
                    <host>node1.source</host>
                    <port>9000</port>
                </replica>
            </shard>
        </source_cluster>
        <destination_cluster>
            <shard>
                <internal_replication>true</internal_replication>
                <replica>
                    <host>node1.dest</host>
                    <port>9000</port>
                </replica>
            </shard>
        </destination_cluster>
    </remote_servers>

    <max_workers>4</max_workers>

    <settings_pull>
        <readonly>1</readonly>
    </settings_pull>

    <settings_push>
        <readonly>0</readonly>
    </settings_push>

    <tables>
        <table_events>
            <cluster_pull>source_cluster</cluster_pull>
            <database_pull>db</database_pull>
            <table_pull>events_source</table_pull>

            <cluster_push>destination_cluster</cluster_push>
            <database_push>db</database_push>
            <table_push>events_target</table_push>

            <engine>
                <engine>ReplicatedMergeTree</engine>
                <shard>01</shard>
                <replica>node1</replica>
            </engine>

            <where_condition>event_time >= '2024-01-01'</where_condition>
        </table_events>
    </tables>
</yandex>
EOF

# 3. 启动
clickhouse-copier \
    --config=/etc/clickhouse-copier/task.xml \
    --task-id=task-001 \
    --base-dir=/tmp/clickhouse-copier
```

## 7.9 集群扩容实战

### 7.9.1 容量评估

```sql
-- 1. 当前容量
SELECT
    database,
    table,
    formatReadableSize(sum(bytes_on_disk)) AS size,
    sum(rows) AS rows,
    count() AS parts
FROM system.parts
WHERE active
GROUP BY database, table
ORDER BY sum(bytes_on_disk) DESC;

-- 2. 增长趋势
SELECT
    toDate(event_time) AS date,
    formatReadableSize(sum(bytes_on_disk)) AS daily_growth
FROM system.parts
WHERE active
  AND event_time >= today() - 30
GROUP BY date
ORDER BY date;

-- 3. 预测何时需要扩容
WITH
    daily_growth AS (
        SELECT avg(bytes_on_disk) AS daily_bytes
        FROM system.parts
        WHERE active
    )
SELECT
    formatReadableSize(sum(bytes_on_disk)) AS current_size,
    formatReadableSize(sum(bytes_on_disk) * 1.0 / daily_bytes) AS days_to_85_pct;
```

### 7.9.2 扩容方案

#### 方案 1：垂直扩容（加机器资源）

```bash
# 1. 关闭服务
systemctl stop clickhouse-server

# 2. 升级硬件
# - 增加 CPU
# - 增加内存
# - 增加磁盘

# 3. 启动
systemctl start clickhouse-server
```

#### 方案 2：水平扩容（加节点）

**步骤 1：准备工作**
```bash
# 1. 新节点安装
# 2. 配置集群（添加到 remote_servers）
# 3. 启动新节点
systemctl start clickhouse-server
```

**步骤 2：创建新分布式表**
```sql
-- 在所有节点执行
CREATE TABLE events_v2 ON CLUSTER new_cluster AS events
ENGINE = Distributed('new_cluster', 'db', 'events_local', cityHash64(user_id));
```

**步骤 3：双写**
```sql
-- 修改业务代码，同时写入两套
INSERT INTO events (old_cluster);
INSERT INTO events_v2 (new_cluster);
```

**步骤 4：历史数据迁移**
```sql
-- 使用 clickhouse-copier
-- 或
INSERT INTO events_v2_local
SELECT * FROM remote('old_cluster', db.events)
WHERE event_time >= '2024-01-01';

-- 验证
SELECT
    old_count, new_count,
    (new_count - old_count) / old_count * 100 AS diff_pct
FROM (
    SELECT
        (SELECT count() FROM remote('old_cluster', db.events)) AS old_count,
        (SELECT count() FROM events_v2) AS new_count
);
```

**步骤 5：切换查询**
```sql
-- 切换业务层
SELECT * FROM events_v2;  -- 替换为 events_v2
```

**步骤 6：下线老表**
```sql
DROP TABLE events ON CLUSTER old_cluster;
```

## 7.10 跨数据中心方案

### 7.10.1 主从架构

```
主中心（写）                从中心（读）
┌──────────┐              ┌──────────┐
│  ClickHouse  │ ←─异步复制─→ │  ClickHouse  │
│   Master     │              │   Slave     │
└──────────┘              └──────────┘
      ↓                          ↑
   业务写入                    业务读
```

### 7.10.2 双活架构

```
中心 A（写+读）              中心 B（写+读）
┌──────────┐              ┌──────────┐
│  ClickHouse  │ ←─双向同步─→ │  ClickHouse  │
└──────────┘              └──────────┘
```

实现方式：
- 业务层按 user_id 分流
- 不同分片在不同中心
- 跨中心查询通过远端表函数
