# 第 8 章：生产运维

## 8.1 监控体系

### 8.1.1 监控指标分类

```
ClickHouse 监控
├── 系统指标
│   ├── CPU、内存、磁盘、网络
│   ├── 磁盘 IO
│   └── 文件描述符、连接数
├── 服务指标
│   ├── 活跃查询数
│   ├── 查询延迟
│   ├── 副本延迟
│   ├── Parts 数量
│   └── Merge 任务
├── 业务指标
│   ├── 写入速率
│   ├── 查询 QPS
│   ├── 慢查询
│   └── 错误率
└── 资源指标
    ├── 单查询内存
    ├── 单查询扫描行数
    └── 网络 IO
```

### 8.1.2 关键指标查询

```sql
-- 1. 系统指标
SELECT *
FROM system.metrics
WHERE metric LIKE '%Memory%' OR metric LIKE '%CPU%'
ORDER BY metric;

-- 2. 异步指标
SELECT *
FROM system.asynchronous_metrics
WHERE metric LIKE '%Disk%' OR metric LIKE '%Network%';

-- 3. 事件
SELECT
    event,
    value,
    description
FROM system.events
WHERE event LIKE '%Query%' OR event LIKE '%Merge%';

-- 4. Parts 状态
SELECT
    database,
    table,
    count() AS part_count,
    sum(rows) AS total_rows,
    formatReadableSize(sum(bytes_on_disk)) AS total_size,
    min(min_time) AS oldest_part,
    max(max_time) AS newest_part
FROM system.parts
WHERE active
GROUP BY database, table
ORDER BY total_size DESC;
```

### 8.1.4 告警规则

```yaml
# alertmanager rules
groups:
- name: clickhouse
  rules:
  # 慢查询告警
  - alert: ClickHouseSlowQuery
    expr: histogram_quantile(0.95, rate(clickhouse_query_duration_seconds_bucket[5m])) > 10
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "P95 查询延迟 > 10s"

  # 副本延迟
  - alert: ClickHouseReplicaDelay
    expr: clickhouse_replica_absolute_delay > 60
    for: 5m
    labels:
      severity: critical
    annotations:
      summary: "副本延迟 > 60s"

  # 磁盘使用率
  - alert: ClickHouseDiskUsage
    expr: (clickhouse_disk_used_bytes / clickhouse_disk_total_bytes) > 0.85
    for: 10m
    labels:
      severity: warning

  # Parts 过多
  - alert: ClickHouseTooManyParts
    expr: clickhouse_table_parts > 100
    for: 5m
    labels:
      severity: warning

  # 内存使用
  - alert: ClickHouseMemoryHigh
    expr: clickhouse_memory_usage > 50e9
    for: 5m
    labels:
      severity: warning
```

## 8.2 备份与恢复

### 8.2.1 备份方案对比

| 方案 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| clickhouse-backup | 完整、一致 | 停机或快照 | 完整备份 |
| 磁盘快照 | 快速 | 需 LVM/ZFS | 大集群 |
| FREEZE PARTITION | 轻量 | 单机 | 增量备份 |
| 导出到 S3 | 异地容灾 | 慢 | 灾备 |

### 8.2.2 clickhouse-backup 实战

```bash
# 安装
wget https://github.com/AlexAkulov/clickhouse-backup/releases/download/v2.5.5/clickhouse-backup.tar.gz
tar -xzf clickhouse-backup.tar.gz
sudo mv clickhouse-backup /usr/local/bin/

# 配置
cat > /etc/clickhouse-backup/config.yml <<EOF
general:
  remote_storage: s3
  max_backup_bandwidth: 100mb

clickhouse:
  username: default
  password: ""
  host: localhost
  port: 9000
  data_path: /var/lib/clickhouse

s3:
  access_key: AKIA...
  secret_key: ...
  bucket: clickhouse-backups
  endpoint: https://s3.amazonaws.com
  region: us-east-1
  path: backups/
EOF

# 创建备份
clickhouse-backup create backup_$(date +%Y%m%d_%H%M%S)

# 上传到 S3
clickhouse-backup upload backup_20240101_120000

# 列出备份
clickhouse-backup list local
clickhouse-backup list remote

# 恢复
clickhouse-backup download backup_20240101_120000
clickhouse-backup restore backup_20240101_120000
```

### 8.2.3 FREEZE PARTITION（轻量备份）

```sql
-- 1. 冻结分区（创建硬链接到 shadow 目录）
ALTER TABLE events FREEZE PARTITION '202401';

-- 2. 查看 shadow 目录
ls -la /var/lib/clickhouse/shadow/
-- 包含完整数据副本

-- 3. 复制到备份存储
cp -r /var/lib/clickhouse/shadow/data/db/events/202401 /backup/

-- 4. 恢复
cp -r /backup/202401 /var/lib/clickhouse/data/db/events/
DETACH TABLE events;
ATTACH TABLE events;

-- 清理（删除冻结）
ALTER TABLE events UNFREEZE PARTITION '202401';
```

## 8.3 升级策略

### 8.3.1 升级流程

```
1. 备份数据
   clickhouse-backup create pre_upgrade_backup

2. 测试环境升级
   - 验证兼容性
   - 运行冒烟测试
   - 检查 query_log 是否有错误

3. 生产环境滚动升级
   - 先升级副本
   - 验证
   - 升级主

4. 升级后验证
   - 写入正常
   - 副本同步
   - 查询性能
```

## 8.5 故障排查

### 8.5.1 慢查询排查

```sql
-- 1. 找慢查询
SELECT
    query_id,
    user,
    query_duration_ms,
    query,
    read_rows,
    read_bytes,
    memory_usage,
    formatReadableSize(memory_usage) AS mem,
    type
FROM system.query_log
WHERE type > 1
  AND query_duration_ms > 10000
  AND event_time > now() - INTERVAL 1 DAY
ORDER BY query_duration_ms DESC
LIMIT 20;

-- 2. 分析具体查询
SELECT
    query_id,
    -- 每一步耗时
    ProfileEvents['RealTimeMicroseconds'] / 1000 AS real_ms,
    ProfileEvents['UserTimeMicroseconds'] / 1000 AS user_ms,
    ProfileEvents['SystemTimeMicroseconds'] / 1000 AS sys_ms,
    ProfileEvents['OSReadBytes'] AS io_read,
    ProfileEvents['OSWriteBytes'] AS io_write
FROM system.query_log
WHERE query_id = 'xxx'
  AND type > 1;
```

### 8.5.2 副本不同步

```sql
-- 1. 查看复制队列
SELECT
    database,
    table,
    replica_name,
    position,
    type,
    parts_to_merge,
    is_currently_executing,
    last_exception
FROM system.replication_queue
WHERE last_exception != ''
ORDER BY last_exception_time DESC
LIMIT 20;

-- 2. 强制同步
SYSTEM SYNC REPLICA events;

-- 3. 恢复副本
SYSTEM RESTART REPLICA events;
```

### 8.5.3 磁盘空间不足

```bash
# 1. 查看占用
du -sh /var/lib/clickhouse/data/*

# 2. 删除老分区

# 3. 强制 merge 减少 part 数量

# 4. 清理 system.parts 历史
ALTER TABLE system.parts MODIFY TTL event_date + INTERVAL 30 DAY;
```
