# 第 6 章 分词器(Analyzer)深入

## 本章目标

学完本章,你能:

- 说出分词器的**三大组件**(character filter / tokenizer / token filter)及其作用。
- 知道 ES 内置的常用分词器(standard / whitespace / keyword / pattern / language / ik / pinyin)。
- 用 `analyze` API 验证分词结果。
- 自己组装一个 `custom analyzer`。
- 理解 **索引时** 和 **搜索时** 分词器为什么要保持一致(或合理差异)。

---

## 6.1 为什么需要分词

ES 的全文搜索是按 **term** 找文档。如果不分词:

- 搜索"Elasticsearch 教程"时,只能匹配文档里**整段**的"Elasticsearch 教程",无法匹配"**Elasticsearch 入门教程**"。
- 所以需要把文本切成"词",再做匹配。

> `keyword` 字段不分词,因为它要的是"全词匹配"。

---

## 6.2 分词器组成

ES 的 analyzer 是**流水线**,由三部分组成:

```
input text → character filter(s) → tokenizer → token filter(s) → token stream
```

| 阶段 | 作用 | 内置示例 |
| --- | --- | --- |
| Character Filter | 在分词前预处理字符 | `html_strip` 去除 HTML 标签;`mapping` 替换字符 |
| Tokenizer | 按规则切成 token | `standard` 切词;`ik_smart` 中文分词 |
| Token Filter | 对 token 进一步处理 | `lowercase` 转小写;`stop` 去掉停用词;`synonym` 同义词 |

例如 `standard` analyzer:

- 字符过滤器:无。
- 分词器:`standard` 切词。
- token 过滤器:`lowercase`。

---

## 6.3 内置分词器

### 6.3.1 standard

默认分词器,按 Unicode 文本分割算法切词,转小写。支持中英文,中文按**单字**切(所以中文搜索效果差)。

```
POST /_analyze
{
  "analyzer": "standard",
  "text": "Hello World! 你好世界"
}
```

输出:`[hello, world, 你, 好, 世, 界]`

### 6.3.2 simple

按非字母切,小写。比 standard 简单(数字保留)。

### 6.3.3 whitespace

只按空白切,大小写不处理。

### 6.3.4 keyword

不分词,整段作为 1 个 token。常用于 id / 邮箱 / 路径等。

### 6.3.5 pattern

按正则分词:

```
"tokenizer": { "type": "pattern", "pattern": "[\\W]+" }
```

### 6.3.6 language

提供几十种语言分词(english / french / chinese 等)。`chinese` 分词精度差,**中文场景不推荐**。

### 6.3.7 nGram / edge_ngram

按字符做 N 元切,适合**前缀补全**:

```
"tokenizer": { "type": "ngram", "min_gram": 2, "max_gram": 3, "token_chars": ["letter", "digit"] }
```

例:搜索框 "el" → 提示"Elasticsearch"。配合 `search_as_you_type` 字段更省事。

## 6.4 中文分词器 IK

中文分词不能用 standard(切成单字,搜"教程"匹配不到"教学教程")。
主流方案:**IK 分词器**。

### 6.4.1 安装 IK(两种方式)

#### 方式一:插件安装(传统)

```bash
./bin/elasticsearch-plugin install https://get.infini.cloud/elasticsearch/analysis-ik/8.13.4
```

#### 方式二:容器化

Dockerfile:

```
FROM docker.elastic.co/elasticsearch/elasticsearch:8.13.4
RUN ./bin/elasticsearch-plugin install https://get.infini.cloud/elasticsearch/analysis-ik/8.13.4
```

或 docker compose `volumes` 挂插件目录。

### 6.4.2 IK 的两种分词模式

- `ik_smart`:粗粒度,切分少,适合搜索(召回准)。
- `ik_max_word`:细粒度,切分多,适合索引(召回全)。

```
POST /_analyze
{
  "analyzer": "ik_max_word",
  "text": "中华人民共和国国歌"
}
# 输出: [中华人民共和国, 中华人民, 中华, 华人, 人民共和国, 人民, 人, 民, 共, 和, 国, 国歌]
```

```
POST /_analyze
{
  "analyzer": "ik_smart",
  "text": "中华人民共和国国歌"
}
# 输出: [中华人民共和国, 国歌]
```

### 6.4.3 索引时 / 搜索时模式选择

经验:

- **索引时用 `ik_max_word`**:把文档的所有可能切分都建索引(召回更全)。
- **搜索时用 `ik_smart`**:用户输入的查询相对短,粗切分即可(精度更高)。

mapping 示例:

```
"title": {
  "type": "text",
  "analyzer": "ik_max_word",          // 索引分词
  "search_analyzer": "ik_smart"       // 搜索分词
}
```

### 6.4.4 扩展词典

IK 默认词库不全,可加自定义词(产品名 / 行业词):

`config/analysis-ik/` 下加:
- `my_extra.dic`:自定义词(每行一个)。
- `my_stopword.dic`:自定义停用词。
- `IKAnalyzer.cfg.xml`:配置加载哪些词库。

`IKAnalyzer.cfg.xml` 示例:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE properties SYSTEM "http://java.sun.com/dtd/properties.dtd">
<properties>
  <comment>IK Analyzer 扩展配置</comment>
  <entry key="ext_dict">my_extra.dic</entry>
  <entry key="ext_stopwords">my_stopword.dic</entry>
</properties>
```

> 修改后必须重启 ES。

## 6.5 拼音分词器(用于拼音搜索)

`elasticsearch-analysis-pinyin` 插件可以将中文转成拼音,并做切分。
常用于"拼音首字母搜索"。

安装:

```bash
./bin/elasticsearch-plugin install https://get.infini.cloud/elasticsearch/analysis-pinyin/8.13.4
```

mapping 示例:

```
"username": {
  "type": "text",
  "analyzer": "pinyin",
  "fields": {
    "raw": { "type": "keyword" }
  }
}
```

查询时,用户输入"zs" → 匹配"张三"、"张思"。

> 注意:拼音分词器会丢失同音字区分,适合"补全",不适合"精确召回"。

---

## 6.6 同义词(synonym)

ES 提供同义词 token filter,可在索引时 / 搜索时应用。

### 6.6.1 静态同义词文件

`config/analysis/synonyms.txt`:

```
iphone, apple phone
mysql, oracle => 数据库
```

上面两种格式:

- 逗号分隔 → 双向等价(任一查询匹配其他)。
- `=>` → 单向(左边等价到右边,只保留右边的 term)。

注意:在 `=>` 形式下,左边作为查询词,右边作为索引词。

### 6.6.2 在 mapping 中使用

```
{
  "settings": {
    "index": {
      "analysis": {
        "analyzer": {
          "ik_synonym": {
            "type": "custom",
            "tokenizer": "ik_smart",
            "filter": ["synonym"]
          }
        },
        "filter": {
          "synonym": {
            "type": "synonym",
            "synonyms_path": "analysis/synonyms.txt"
          }
        }
      }
    }
  }
}
```

## 6.7 自定义分词器(Custom Analyzer)

```
PUT /test_index
{
  "settings": {
    "analysis": {
      "char_filter": {
        "my_char": {
          "type": "mapping",
          "mappings": [ "- => _", "& => and" ]
        }
      },
      "tokenizer": {
        "my_tok": {
          "type": "pattern",
          "pattern": "[\\s\\|]+"
        }
      },
      "filter": {
        "my_lower":  { "type": "lowercase" },
        "my_stop":   { "type": "stop",     "stopwords": ["_english_"] },
        "my_synonym": { "type": "synonym",  "synonyms": ["js, javascript"] }
      },
      "analyzer": {
        "my_analyzer": {
          "type": "custom",
          "char_filter": ["my_char"],
          "tokenizer":    "my_tok",
          "filter":       ["my_lower", "my_stop", "my_synonym"]
        }
      }
    }
  }
}
```

调试分词:

```
POST /test_index/_analyze
{ "analyzer": "my_analyzer", "text": "Hello JS | Welcome" }
```

## 6.8 用 analyze API 调试

```
GET /_analyze
{
  "analyzer": "ik_smart",
  "text": "中华人民共和国国歌"
}
```

> 不必指定 index 即可对内置 analyzer 调试验证。

也可用 `explain: true` 看每步执行:

```
GET /_analyze
{
  "tokenizer": "standard",
  "filter":   ["lowercase"],
  "text":     "Hello World!",
  "explain":  true
}
```

## 6.9 索引分词 vs 搜索分词

一般两种分词器分开:

- **index_analyzer**:`text` 字段索引时用的分词器。默认与 `analyzer` 一致。
- **search_analyzer**:搜索时用的分词器。默认与 `analyzer` 一致。

不同分词器场景:

| 场景 | index | search |
| --- | --- | --- |
| 中文搜索 | ik_max_word | ik_smart |
| 英文搜索 | standard | standard(无需区别) |
| 拼音补全 | pinyin | pinyin |
| 同义词 | standard + synonym | standard + synonym |

> 严格地说,搜索时还要考虑 **search_analyzer vs search_quote_analyzer**:
> - `search_analyzer` 用在普通 query(如 `match`)。
> - `search_quote_analyzer` 用在 `match_phrase` 上(对短语中的每个 term 重新分词)。

## 6.10 词干提取 / 词形还原

英文场景下,搜索"running"应匹配"run"。内置 `english` analyzer 自带:

- `lowercase`
- `stop`
- `porter_stem`(Porter 词干)
- `stemmer`(更精确的 Snowball)

自定义:

```
"filter": { "my_stemmer": { "type": "stemmer", "language": "english" } }
```

注意:中文不需要词干提取;但英文同义 / 形变要处理。

---

## 6.11 stopwords(停用词)

"the"、"a"、"了"、"的" 等无意义词。
ES 自带 `_english_` 列表。中文常见停用词需自定义。

注意:不要无脑去停用词。搜索引擎需要"召回全",有时停用词是定位关键短语的关键(比如"The Who" 乐队名)。

---

## 6.12 高频踩坑

1. **standard analyzer 用于中文搜索 → 召回差**。永远用 `ik` / `hanlp` / `smartcn`。
2. **索引时用 ik_smart,搜索时用 ik_max_word**:召回率下降。
3. **同义词文件** 改动后必须 **close → open index** 才会重新加载。
4. **拼音分词**对多音字处理差,不适合"唯一"召回。
5. **ngram 太短**(min_gram=1)会占巨大空间,通常从 2 开始。
6. 启用 `_analyzer` 调试,先确认分词结果,再排查搜索问题。

---

## 6.13 要点速查

- analyzer = char_filter + tokenizer + token_filter。
- 中文必装 IK;`ik_max_word` 用于索引,`ik_smart` 用于搜索。
- 拼音用 `pinyin` 插件,补全场景。
- 同义词用 `synonym` filter,放 search_analyzer 里更省事。
- 自定义 analyzer 通过 index settings 装配。
- `_analyze` 是调试利器。

---

## 6.14 实操练习

1. 安装 IK + 拼音插件。
2. 写 `custom analyzer`,组合 `ik_smart + lowercase + pinyin_filter`,让中英文 + 拼音都能搜。
3. 配置同义词文件:如 `js, javascript, ts` 等价。
4. 用 `_analyze` 验证:`"中华人民共和国国歌"` 在 ik_max_word / ik_smart 下的切分。
