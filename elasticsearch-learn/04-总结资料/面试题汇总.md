# Elasticsearch 面试题汇总(2026 精编)

> 涵盖 入门 / 进阶 / 高级 / 专家 4 个级别。
> 每题有"**考察点**"提示,先想再看答案。

---

## 入门 10 题

### Q1. Elasticsearch 是什么?与 MySQL / MongoDB 有什么区别?

**答**:ES 是基于 Lucene 的 **分布式搜索与分析引擎**,近实时(NRT),用 RESTful API。
与 MySQL(MRDB)区别:

| 维度 | MySQL | ES |
| --- | --- | --- |
| 核心能力 | 事务(ACID) | 全文搜索 + 聚合分析 |
| 数据模型 | 表 / 行 / 列 | index / doc / field |
| 倒排索引 | 无(Fulltext 慢) | 内置 |
| 事务 | 强 | 弱(单文档) |
| 容量 | GB~TB | TB~PB |
| 适用 | 业务写 | 搜索 / 日志 / 分析 |

MongoDB 是文档型库,介于两者之间。

---

### Q2. 什么是倒排索引?

**答**:正向索引是 `文档 → 内容`,倒排索引是 `term → 文档列表`。
例:3 篇文档,倒排索引记录每个词出现在哪些文档 + 词频 + 位置(用于 phrase / 评分)。

> Lucene 用 FST + 跳表 + postings list 实现。

---

### Q3. ES 集群中 cluster / node / index / shard / document 是什么关系?

**答**:

- **Cluster**:集群,由多个 node 组成。
- **Node**:一个 ES 进程。
- **Index**:一类文档的集合,逻辑概念。
- **Shard**:index 物理切分单位,每个 shard 是一个 Lucene index。
- **Document**:一条 JSON,index 的最小单位。

---

### Q4. 什么是 primary shard 与 replica?创建后能改吗?

**答**:

- **primary shard**:主分片,负责写;创建 index 时定,不可改。
- **replica**:副本,从 primary 复制,可随时改。
- 主副本不在同一节点(强约束)。

> 改 primary 数 = reindex(用 shrink / split 可有限扩)。

---

### Q5. 解释 NRT(近实时)。写入后多久可搜?

**答**:`refresh_interval`(默认 1s)把内存中的 segment 刷到 filesystem cache,生成新的可搜 segment。
强制立即可搜:`POST /index/_refresh`(测试用)。

---

### Q6. PUT 与 POST 写文档有什么区别?

**答**:

- `PUT /index/_doc/<id>`:**必带 id**,可覆盖(幂等)。
- `POST /index/_doc`:**自动生成 id**,不覆盖(非幂等)。
- 局部更新用 `POST /_update/<id>`(底层 read-then-replace)。

---

### Q7. _bulk 是什么?为什么生产必用?

**答**:`_bulk` 一次提交多条写入/更新/删除请求(每条两行 NDJSON,delete 一行)。
生产必用原因:减少 HTTP round-trip,降低每个文档的协调开销。
建议批次 5~15 MB,过大反而 OOM。

---

### Q8. match 和 term 有什么区别?

**答**:

- `match`:会分词(text 字段),适合全文搜索。
- `term`:**不分词**,精确匹配。匹配 text 字段要 `.keyword`。

---

### Q9. ES 如何做乐观锁?

**答**:通过 `if_seq_no` + `if_primary_term` 防止并发覆盖。
不匹配 → 返回 409,客户端重试或回滚。
`_version` 从 7.x 起 deprecated。

---

### Q10. text 和 keyword 字段有什么区别?

**答**:

- `text`:分词 + 倒排,全文搜索。
- `keyword`:不分词,精确匹配 + 聚合 + 排序。
- 多字段:`text` 配 `fields.raw: keyword` 同时具备两种能力。

---

## 进阶 15 题

### Q11. 写出 text + keyword + numeric + date + geo_point 的 mapping 例子。

**答**:见 [第 5 章 Mapping](../01-进阶篇/05-Mapping与字段类型详解.md)。要点:

- text 配 ik_max_word 索引 / ik_smart 搜索。
- 金额用 scaled_float。
- 经纬度用 geo_point。

---

### Q12. 怎么用 IK?`ik_smart` vs `ik_max_word`?

**答**:IK 是中文分词器。

- `ik_max_word`:细粒度,切分多,索引用,召回全。
- `ik_smart`:粗粒度,搜索用,精度高。

> 索引用 `max_word`、搜索用 `smart` 是生产经验。

---

### Q13. bool query 中 must / should / filter / must_not 的区别?

**答**:

- `must`:必须,打分。
- `should`:可选,打分;无 must 时至少 1 个。
- `filter`:必须,**不打分**,可缓存。
- `must_not`:反向,不打分。

> 能 filter 的就 filter,效率高。

---

### Q14. 什么是 query context 与 filter context?

**答**:

- **Query context**:会算 `_score`(相关性)。
- **Filter context**:只判断匹配 / 不匹配,不打分,可缓存,效率高。

---

### Q15. multi_match 的 type 区别?电商用什么?

**答**:

- `best_fields`(默认):取单字段最高分。
- `most_fields`:多字段分数求和。
- `cross_fields`:跨字段视作整体。
- `phrase` / `phrase_prefix` / `bool_prefix`:短语 / 前缀。

电商"商品搜索"通常用 `best_fields`(title 命中更重要)。

---

### Q16. 怎么深分页?from+size 限制多少?

**答**:`from + size` 默认 ≤ `index.max_result_window`(10000)。
超了会报错或极慢。改用:

- `search_after` + 稳定 sort。
- PIT(point in time)。
- 不支持跳页,只能顺序翻。

---

### Q17. terms / date_histogram / composite agg 怎么选?

**答**:

- `terms`:固定字段分桶,top N(精度问题)。
- `date_histogram`:时间分桶。
- `composite`:分桶分页(高基数 / 全分桶)。

---

### Q18. 聚合结果为什么"不精确"?

**答**:`terms` 在每个 shard 取 top N,再合并。
某 term 在 shard A 是 top5、shard B 是 top20,合并时可能漏。
解决:调大 `shard_size`(1.5~2x size),或 `composite`。

---

### Q19. 解释 nested 与 object 的区别。

**答**:ES 默认 `object` 字段扁平化(数组里所有 `name` 放一字段),**丢失关联**。
`nested` 把每条数组项存为独立隐藏文档,可独立查询。
代价:索引体积大,查询开销大。

---

### Q20. dense_vector 是什么?用在哪?

**答**:`dense_vector` 存浮点向量,支持 **kNN** 检索(ANN 算法)。
用于 RAG / 语义搜索 / 图像检索。
`dims` 维度越大越准,但内存与计算成本越高。

---

### Q21. highlight 内部怎么工作?代价?

**答**:用 `unified` / `plain` / `fvh` 重新跑分词,从 source 取片段包 `<em>`。
性能成本:需要重新访问 source + 计算。
`fvh`(fast vector highlighter)需 `term_vector: with_positions_offsets`,更快但写入大。

---

### Q22. 什么是 completion suggester?与 search_as_you_type 区别?

**答**:

- **completion**:FST 实现,极快,但只能前缀。
- **search_as_you_type**:多个 subfield 支持中间词匹配,较灵活。

---

### Q23. 怎么排查一个"搜不到"的 query?

**答**:

1. `_analyze` 验证分词。
2. `validate/query?explain=true` 验证 DSL。
3. `explain=true` 看每个文档的 _score 公式。
4. profile=true 看耗时阶段。
5. 检查 mapping(字段是否 keyword?分词器对吗?)。
6. 查是否 data stream 不允许 update。

---

### Q24. _source 是什么?关掉会怎样?

**答**:存原始 JSON。关掉:

- 失去 update / reindex 能力。
- 失去 highlight。
- 失去 painless script 读源。
- 节省 ~10%~30% 存储。

> 一般不关。

---

### Q25. dynamic mapping 策略?生产用哪个?

**答**:

- `true`(默认):自动加字段,易爆炸。
- `false`:能存但不索引。
- `strict`:出现新字段直接报错。
- `runtime`:作为运行时字段。

> 生产推荐 `strict` 或配合 dynamic_templates 显式管理。

---

## 高级 15 题

### Q26. 解释 BM25 公式,各部分含义。

**答**:

$$
\text{score} = \sum_{t \in Q} IDF(t) \cdot \frac{tf(t, D) \cdot (k_1+1)}{tf(t, D) + k_1 \cdot (1-b+b \cdot |D|/\text{avgdl})}
$$

- `tf`:词频。
- `IDF`:逆文档频率,稀有词权重大。
- `|D|`:文档长度;`avgdl`:平均长度。
- `k1`(默认 1.2):TF 饱和控制。
- `b`(默认 0.75):长度归一化。

---

### Q27. function_score 怎么融合业务权重?

**答**:用 `functions` 数组组合 `weight` / `field_value_factor` / `gauss` 等,通过 `score_mode` 合并函数分,再 `boost_mode` 与原 query 分组合(常用 multiply / sum)。

例:相关性 × 销量 log × 时间衰减。

---

### Q28. ES 写入流程(translog / refresh / flush)。

**答**:

1. 写 translog(同步落盘)。
2. 写内存 buffer。
3. refresh(默认 1s):buffer → filesystem cache(可搜)。
4. 每 30 分钟 / translog 大:flush → segment + 切 translog。

> translog 保证宕机不丢;segment 不可改,只能 merge。

---

### Q29. 单 shard 多大合适?为什么?

**答**:**10~50 GB**。
太小:分片多,资源浪费,merge 慢。
太大:recovery 慢,merge 慢,GC 慢。

---

### Q30. 副本数怎么选?写多 / 读多场景。

**答**:

- 数据可靠性:副本 ≥ 1。
- 写密集:副本 0 写,再加(写时副本是 bottleneck)。
- 读密集:副本多,搜索可分摊。
- 集群规模:副本 ≤ 节点数 - 1。

---

### Q31. 解释 ILM 的 4 阶段。

**答**:

- **Hot**:写入密集,SSD。
- **Warm**:读多写少,降配。
- **Cold**:极少读,HDD / 普通磁盘。
- **Frozen**:对象存储(S3),本地几乎不占。

`min_age` 从 **rollover 时间**算起。

---

### Q32. Data Stream 是什么?与普通 index 区别?

**答**:**8.x 新**,append-only 场景(日志 / 指标)。
内部对应多个 backing index(`-000001`),自动 rollover。
- 写必须用 `_create`。
- 拒绝 `_doc` / `_update` / `_delete`。
- 简化开发,适合"事件流"。

---

### Q33. 集群 master 选举怎么防脑裂?

**答**:

- 至少 3 个 master eligible 节点(odd)。
- majority 算法:`floor(N/2)+1`。
- 网络分裂超过 majority 才允许选主。
- ES 7.x 起自动算 `minimum_master_nodes`,无需手动设。
- 避免 GC / 磁盘满导致假死。

---

### Q34. cluster state 是什么?多大合适?

**答**:集群全局元数据(index / mapping / settings / shard 位置)。
master 节点维护,通过 2PC 同步。
state 越大(单 index mapping 巨大、shard 数多)→ master 内存 / 网络压力大。
优化:减少 index 数(用数据流 / 滚动),简化 mapping。

---

### Q35. 写入流程为什么副本数多会拖慢?

**答**:主分片写完 → 转发到所有副本 → 副本成功 → 主分片成功。
副本数 = 副本转发次数 + 副本刷盘次数。
副本越多,latency 越高,出错率越高。

---

### Q36. search 流程的两阶段是什么?

**答**:

- **Query phase**:每个 shard 内部算 top-K(文档 id + score),返回给协调节点。
- **Fetch phase**:协调节点 merge + 全局排序后,回各 shard 取 `_source` + highlight。

---

### Q37. ES 调优 checklist。

**答**:

- 写:bulk 5~15MB / refresh 30s+ / translog async / 副本 0 写。
- 查:filter 优先 / search_after / routing / request_cache。
- 索引:单 shard 10~50G / 角色分离 / ILM。
- JVM:Xms = Xmx = 物理 / 2(≤ 64G)或 32G / G1GC / 关 swap。
- 集群:3 master / odd / 慢日志 / SLM。

---

### Q38. JVM heap 为什么建议 ≤ 32G?

**答**:超过 32G,指针压缩失效(Compressed Oops,基于 4G 寻址),JVM 内存翻倍,GC 显著变慢。
32G + 强 FS Page Cache 是 Lucene 黄金搭档。

---

### Q39. 节点 OOM 怎么定位?

**答**:

1. `/_nodes/hot_threads` 看占用最高线程。
2. heap dump:`jmap -dump:live,format=b,file=heap.bin <pid>`。
3. MAT / VisualVM 分析大对象。
4. 常见:fielddata 爆 / 大聚合 / 深分页 / 大量并发 query。

---

### Q40. 怎么定位"集群写入慢"?

**答**:

1. `/_cat/thread_pool/write?v&h=node_name,active,queue,rejected` 看写队列。
2. `/_nodes/stats/indices/indexing` 看 index throttle 时间。
3. 慢日志 `logs/*_indexing_slowlog.log`。
4. 检查 `index.merge.*` 是否被大 segment 卡住。
5. disk IO:`iostat -x 1`。
6. 常见原因:副本多 / 段合并 / refresh 太频繁。

## 专家 20 题

### Q41. CCR 与 CCS 的核心区别?

**答**:

- **CCR**:跨集群**复制**数据(写一次,远端同步),Platinum。
- **CCS**:跨集群**搜索**(查询时聚合多集群结果),基础免费。

---

### Q42. ES 8.x 默认开启 security 吗?为什么?

**答**:**是**。8.x 起默认开启 xpack.security + HTTPS,要求账号密码登录。
原因:安全合规、默认安全。

---

### Q43. API Key 与密码的区别?服务间用哪个?

**答**:

- **密码**:长期,与用户绑定;权限粒度粗;泄露影响用户所有操作。
- **API Key**:可设过期 / 细粒度权限;吊销灵活;服务间调用首选。

---

### Q44. DLS / FLS 是什么?场景?

**答**:

- **DLS**(Document Level Security):通过 query 限定"能看哪些文档",类似 SQL row-level security。多租户场景。
- **FLS**(Field Level Security):限定"能看哪些字段",屏蔽敏感字段(token / 身份证)。
- 都需要 X-Pack Platinum。

---

### Q45. 自定义分词器插件怎么写?生命周期?

**答**:实现 `AnalysisPlugin` 接口,注册 `analyzer` / `tokenizer` / `filter`。
Gradle + elasticsearch.esplugin 插件构建,产出 zip,`elasticsearch-plugin install`。
插件目录在 `$ES_HOME/plugins/<name>/`。
8.x 默认要求插件签名。

---

### Q46. 解释 ES 在 RAG 中的角色。

**答**:RAG = 检索增强生成。ES 作为"检索引擎":

- BM25 找精确词命中。
- dense_vector + knn 找语义近。
- 混合召回 → top K → LLM 拼成 prompt 生成答案。

ES 提供"原文依据",可溯源。

---

### Q47. 索引模板(Index Template)与 Component 模板。

**答**:

- **Index Template**:index 创建时套用,8.x 推 `composable` 写法。
- **Component Template**:可复用片段,被 index template 引用(`composed_of`)。

> Component 模板管 settings,mapping 单独管,组合用。

---

### Q48. 集群 red 的处理流程。

**答**:

1. `GET /_cluster/health` 确认。
2. `GET /_cluster/allocation/explain` 看 unassigned 原因。
3. 常见:
   - 磁盘满 → 清 / 扩。
   - 配置限分片 → 改 `cluster.routing.allocation.*`。
   - 节点 down → 重启 / 替换。
4. 实在无法恢复:`POST /_cluster/reroute` 强制分配(丢数据风险)。

---

### Q49. 解释 searchable snapshot。

**答**:把冷数据放对象存储(S3),本地不存,查询时按需拉 segment 到本地 cache。
7.12+ 引入,frozen tier 的核心。
适合"低频但要查"的合规数据。

---

### Q50. 解释 shard allocation explain。

**答**:`GET /_cluster/allocation/explain` 返回每个 unassigned shard 的"为什么没分出去"。
- 磁盘阈值超
- 节点过滤不满足
- 分配被禁用
- 节点离线
- 版本不兼容

> 排错的"第一道 API"。

---

### Q51. ES 与 ClickHouse 选哪个?

**答**:

- **ES**:全文搜索 / 日志 / 文档 / 向量,长文本模糊查。
- **ClickHouse**:OLAP 大宽表聚合,列存极致压缩,毫秒级聚合亿级。

> 日志 + 简单统计用 ES;纯聚合(广告效果、用户画像)用 ClickHouse。

---

### Q52. ES 与 OpenSearch 区别?

**答**:

- OpenSearch 是 AWS 在 7.10.2 基础上的 fork,Apache 2.0 协议。
- API 高度兼容,但已分化(部分新功能 / 商业特性差异)。
- 选型:用 Elastic 服务 / 商业功能选 ES;想要纯开源 / 避免 vendor lock 选 OpenSearch。

---

### Q53. 解释 shard size / shard count / 节点数 的容量公式。

**答**:

- 数据量 1TB,期望单 shard 30GB → 主分片数 = 33。
- 节点数 5,副本 1 → 实际 66 个分片(33 主 + 33 副本),每节点 ~13 个分片。
- 每节点磁盘 = 数据 × (1 + 副本) / 节点数 = 1TB × 2 / 5 = 400GB。
- 预留 30%~50% → 实际配 600GB。

---

### Q54. 写后立刻查不到?为什么?

**答**:写入走"buffer → refresh",默认 1s 才可搜。
强制立即可搜:`POST /index/_refresh`。
生产调整 `index.refresh_interval`,平衡实时性 vs 写入性能。

---

### Q55. 怎么验证我的索引设计是对的?

**答**:

1. `GET /index/_mapping` 看是否符合预期。
2. `_analyze` 验证分词结果。
3. `validate/query?explain=true` 验证 DSL 命中期望字段。
4. 真实查询 + `explain=true` 看打分构成。
5. 写一个 `_profile` 跑压测,看瓶颈。
6. 写 A/B 切流对比 CTR / 转化。

---

### Q56. 滚动升级流程。

**答**:

1. 禁 shard 分配:`PUT /_cluster/settings {"transient": {"cluster.routing.allocation.enable": "primaries"}}`。
2. 停 / 升级一个节点。
3. 等集群状态变绿,再下一个。
4. 全做完,恢复默认分配。

> 跨大版本(7 → 8)需先升到中间版。

---

### Q57. ES 怎么防"上游字段爆炸"?

**答**:

- `dynamic: strict` 直接拒。
- `dynamic: false` + ingest pipeline 过滤字段。
- `dynamic_templates` 把所有 string 限定为 keyword。
- 在 ES 前置一层网关 / Kafka 做 schema 校验。

---

### Q58. 怎么决定用 routing?

**答**:

- **多租户**:按 `tenant_id` routing,查询只走 1 个 shard。
- **业务隔离**:大品牌 / 大商户自营 routing。
- 风险:租户倾斜 → 热点 shard → 拆租户 / 加节点。
- 评估:80% 流量是否集中少数租户。

---

### Q59. ES 集群 100 个节点,master 怎么设?

**答**:

- **3 个 master only 节点**(2 核 8G,无 data 角色)。
- data 节点按业务 / 硬件分角色(ingest / hot / warm / cold)。
- coordinating 节点单独部署(扛高并发查询)。
- 用 `node.roles` 显式声明。

---

### Q60. 跨集群场景选什么方案?

**答**:

| 场景 | 方案 |
| --- | --- |
| 异地多活读 | CCR + CCS |
| 异地多活写(双写) | 业务双写 + 异步对账 |
| 灾备 | CCR / Snapshot |
| 跨集群聚合报表 | CCS |

### Q61. 设计一个 100 亿条订单的搜索系统。

### Q63. 如何从 0 设计一个电商搜索的"权重融合"?

**答**:

1. 基础相关性 BM25,字段加权 `title^3, tags^2`。
2. function_score 加:
   - 销量(log1p,避免爆大)。
   - 评分(sqrt)。
   - 新品(gauss 时间衰减)。
   - 官方 / 自营(weight)。
3. `boost_mode: sum` 合并业务与相关性。
4. 上线前 A/B 对比,CTR / 转化。

### Q64. ES 写入瓶颈在哪里?怎么压测?

**答**:

- 写瓶颈:副本转发 / segment merge / disk IO。
- 压测工具:esrally 跑 geonames / nyc_taxis;wrk / vegeta 自定义。
- 调优:副本 0 写 / bulk 5~15MB / refresh 30s / translog async / SSD。

### Q65. ES 与向量数据库(Milvus / Qdrant)的区别?

**答**:

- **ES** + dense_vector:一体化存储(结构化 + 向量),中等规模,knn + filter 强。
- **Milvus / Qdrant**:纯向量数据库,亿级向量,ANN 算法丰富,无结构化过滤。

> 业务上:既要全文也要语义 → ES hybrid;纯语义 → Milvus。

### Q66. 怎么在 ES 上做"长事务" / "并发写"?

**答**:

- ES 不支持 ACID 事务。
- 写并发:用 `_seq_no + _primary_term` 做乐观锁。
- 跨文档"事务":业务侧用 `try { 写多个 } catch { 回滚 }`,但部分成功不保证。

---

### Q67. 解释 shard recovery 流程。

**答**:节点加入 / 主分片丢失 → 从其他副本拉 segment。
阶段:
- **init**:初始化(建 translog)。
- **index**:拉 segment 验证。
- **verify_index**:对账。
- **translog**:replay 增量。
- **finalize** → done。

限速:`index.recovery.max_bytes_per_sec`。

### Q68. ES 8.x vs 7.x 重大变化。

**答**:

- 默认开启 Security / HTTPS。
- Mapping types 完全移除(6.x 开始)。
- ILM 改 Data Stream。
- 删 `_doc` 类型 8.x 已默认。
- Painless + runtime fields。
- dense_vector 强,k-NN 优化。
- ES 8.13 / 8.14 持续小迭代。

### Q69. 怎么从 0 选 ES 版本?

**答**:

- 生产:最新稳定大版本 +1~2 个月内(避免 bug 高发期)。
- 长期:跟官方大版本走(每 1~2 年一版)。
- 7.x → 8.x:必须先升 7.17(最后 7.x),再升 8.x。
- 强烈建议升级到 8.x 享受免费 alerting / SIEM / 性能优化。

### Q70. ES 在 AI 时代的位置?
