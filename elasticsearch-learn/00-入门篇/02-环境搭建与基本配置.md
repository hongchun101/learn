# 第 2 章 环境搭建与基本配置

## 本章目标

学完本章,你能:

- 在本地 / 服务器上启动一个单节点 ES + Kibana 集群。
- 通过 `curl` 或 Kibana Dev Tools 调用 ES API。
- 了解 ES 8.x 默认安全配置、HTTPS、密码生成逻辑。
- 掌握 `elasticsearch.yml` 的关键配置项。

---

## 2.1 准备环境

### 2.1.1 硬件建议

| 角色 | 最低 | 推荐 |
| --- | --- | --- |
| 学习用(单节点) | 2C4G | 4C8G |
| 生产(3 节点起步) | 8C16G | 16C64G |
| 磁盘 | 50G SSD | 1T+ SSD |

### 2.1.2 软件依赖

- **JDK**:ES 8.x 要求 **JDK 17+**(7.x 用 JDK 8)。
- **OS**:Linux 主流发行版 / macOS / Windows(Windows 上需要 WSL2 才能跑)。
- **网络**:能下载 Docker 镜像或官方 tarball。

### 2.1.3 重要系统参数(Linux)

ES 对系统资源有要求,生产环境务必调整:

```bash
# 1) 关闭 swap(ES 启动会检查;必须关闭或设为 1)
sudo swapoff -a

# 2) 调整虚拟内存与文件描述符
cat >> /etc/security/limits.conf <<EOF
* soft nofile 65536
* hard nofile 65536
* soft nproc 4096
* hard nproc 4096
EOF

# 3) 调整 vm.max_map_count
sudo sysctl -w vm.max_map_count=262144
# 持久化:
echo "vm.max_map_count=262144" | sudo tee -a /etc/sysctl.conf
```

## 2.2 安装方式

### 2.2.1 方式一:Docker(推荐新手)

```bash
# 拉取镜像
docker pull docker.elastic.co/elasticsearch/elasticsearch:8.13.4
docker pull docker.elastic.co/kibana/kibana:8.13.4

# 创建网络
docker network create elastic

# 启动 ES(单节点 + 安全开启)
docker run --name es01 --net elastic -p 9200:9200 \
  -e "discovery.type=single-node" \
  -e "xpack.security.enabled=true" \
  -e "xpack.security.http.ssl.enabled=false" \
  -e "ES_JAVA_OPTS=-Xms512m -Xmx512m" \
  docker.elastic.co/elasticsearch/elasticsearch:8.13.4

# 启动 Kibana
docker run --name kib01 --net elastic -p 5601:5601 \
  -e "ELASTICSEARCH_HOSTS=http://es01:9200" \
  docker.elastic.co/kibana/kibana:8.13.4
```

启动后,容器日志会**自动生成 elastic 用户的随机密码**。请立即复制:

```bash
docker logs es01 | grep -i "password"
# 输出形如:
# ELASTIC_PASSWORD=AbCdEfGh12345678
```

> 如果你想指定固定密码(学习阶段),改为 `-e "ELASTIC_PASSWORD=yourpass"`,但只在测试环境使用。

### 2.2.2 方式二:Docker Compose(更整洁)

`docker-compose.yml`:

```yaml
version: "3.8"
services:
  elasticsearch:
    image: docker.elastic.co/elasticsearch/elasticsearch:8.13.4
    environment:
      - discovery.type=single-node
      - xpack.security.enabled=true
      - xpack.security.http.ssl.enabled=false
      - ELASTIC_PASSWORD=es123456
      - ES_JAVA_OPTS=-Xms512m -Xmx512m
    ports: ["9200:9200"]
    volumes:
      - es_data:/usr/share/elasticsearch/data
  kibana:
    image: docker.elastic.co/kibana/kibana:8.13.4
    environment:
      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
      - ELASTICSEARCH_USERNAME=kibana_system
      - ELASTICSEARCH_PASSWORD=es123456
    ports: ["5601:5601"]
    depends_on: [elasticsearch]
volumes:
  es_data:
```

> 注意:8.x Kibana 需要 `kibana_system` 用户才能连接 ES。`elastic` 超级用户在 Kibana 也可以登录,但推荐用系统用户。系统用户的密码可用命令重置:

```bash
docker exec -it es01 /usr/share/elasticsearch/bin/elasticsearch-reset-password \
  -u kibana_system -i
```

### 2.2.3 方式三:tarball 安装(Linux)

```bash
wget https://artifacts.elastic.co/downloads/elasticsearch/elasticsearch-8.13.4-linux-x86_64.tar.gz
tar -xzf elasticsearch-8.13.4-linux-x86_64.tar.gz
cd elasticsearch-8.13.4
./bin/elasticsearch   # 前台启动
```

Kibana 同理:

```bash
wget https://artifacts.elastic.co/downloads/kibana/kibana-8.13.4-linux-x86_64.tar.gz
tar -xzf kibana-8.13.4-linux-x86_64.tar.gz
cd kibana-8.13.4
./bin/kibana
```

  },

### 2.3.2 查看集群健康

```bash
curl -u elastic:es123456 http://localhost:9200/_cluster/health
```

返回:

```json
{
  "cluster_name": "elasticsearch",
  "status": "green",   // green / yellow / red
  "number_of_nodes": 1,
  "number_of_data_nodes": 1,
  "active_primary_shards": 0,
  ...
}
```

颜色含义:
- **green**:所有主分片与副本都正常。
- **yellow**:所有主分片可用,但有副本缺失(单节点自带的副本不算)。
- **red**:有主分片不可用。

### 2.3.3 用 Kibana Dev Tools

打开 `http://localhost:5601`,登录后进入 **Dev Tools**(左下角菜单)。它自带格式化与历史记录,强烈推荐。

输入:

```
GET /_cluster/health
```

点执行(▶),右侧出现响应。

## 2.4 elasticsearch.yml 关键配置

`config/elasticsearch.yml` 是主配置文件。下面是高频配置项(8.x):

```yaml
# ----- 集群 -----
cluster.name: my-cluster          # 集群名,同一集群必须相同
node.name: node-1                 # 节点名(可不写,默认随机)
node.roles: [master, data, ingest]  # 节点角色(8.x 推荐显式写)

# ----- 网络 -----
network.host: 0.0.0.0             # 监听 IP(默认 127.0.0.1)
http.port: 9200                   # HTTP 端口
transport.port: 9300              # 节点间通信端口

# ----- 路径 -----
path.data: /var/lib/elasticsearch
path.logs: /var/log/elasticsearch

# ----- 发现 -----
discovery.seed_hosts: ["node1", "node2", "node3"]  # 用于发现 master
cluster.initial_master_nodes: ["node-1", "node-2", "node-3"]  # 首次启动

# ----- 安全(8.x 默认开启) -----
xpack.security.enabled: true
xpack.security.enrollment.enabled: true
xpack.security.http.ssl:
  enabled: true
  keystore.path: certs/http.p12
xpack.security.transport.ssl:
  enabled: true
  verification_mode: certificate
  keystore.path: certs/transport.p12
  truststore.path: certs/transport.p12

# ----- 内存 / 线程 -----
# 实际内存请用 jvm.options,不在这里设置
thread_pool.write.queue_size: 1000
```

## 2.5 JVM 设置

ES 的 JVM 内存对性能影响巨大。改 `config/jvm.options`:

```
-Xms4g
-Xmx4g
```

两个值**必须相同**,避免运行时动态扩缩容带来的 GC 问题。

经验:

- 物理内存 ≤ 64G:**Xms 与 Xmx 设为物理内存的 50%**。
- 物理内存 > 64G:ES 推荐 32G 上限,其余留给文件系统缓存(因为 Lucene 高度依赖 OS Page Cache)。
- 单节点学习:512M 即可。

## 2.6 启动多节点集群(本地 docker)

```bash
# 节点 1
docker run --name esn1 -p 9200:9200 -p 9300:9300 \
  -e node.name=esn1 \
  -e cluster.name=es-cluster \
  -e discovery.seed_hosts=esn2,esn3 \
  -e cluster.initial_master_nodes=esn1,esn2,esn3 \
  -e xpack.security.enabled=false \
  -e ES_JAVA_OPTS="-Xms512m -Xmx512m" \
  --network=elastic \
  -d docker.elastic.co/elasticsearch/elasticsearch:8.13.4
```

同理启动 esn2 / esn3,改 `--name` / `node.name` / 端口即可。

## 2.9 常见启动问题速查

| 错误 | 原因 | 解决 |
| --- | --- | --- |
| `max virtual memory areas vm.max_map_count [65530] is too low` | 系统参数不够 | `sysctl -w vm.max_map_count=262144` |
| `the default discovery settings are unsuitable for production use` | 没设 `discovery.seed_hosts` | 显式设 `discovery.type=single-node` 或加 seed |
| `node is not allowed to join` | 节点 `cluster.name` 不一致 | 改一致 |
| `Connection refused 9200` | 没监听外部 | 设 `network.host: 0.0.0.0` |
| 8.x 一直要求账号密码 | 8.x 默认开启 security | 用 `elastic` 用户登录,或 `xpack.security.enabled=false` |
| `Java version X is not supported` | JDK 版本低 | 升到 17 |

## 2.10 要点速查

- 8.x 默认开启安全、HTTPS,推荐 docker 起步。
- 单机学习:`discovery.type=single-node` + 内存设 512M。
- `elasticsearch.yml` 控制集群/网络/路径/发现/安全。
- `jvm.options` 控 JVM 堆,**Xms = Xmx**。
- `GET /` 看版本;`GET /_cluster/health` 看状态。
- Kibana Dev Tools 是最方便的手工调试工具。
