# 第 1 章  动机与历史:为什么函数式编程

> 读完本章,你能回答:函数式编程"是什么"和"为什么";它与命令式编程在思维模型上的根本差异;以及过去 90 年它是如何从 λ-演算走到工程主流的。

## 1.1 两类世界观

### 1.1.1 命令式:模拟图灵机

命令式编程继承了冯·诺依曼体系,核心隐喻是**带状态的内存**。程序由一系列改变内存的指令组成,语义模型是图灵机:

```
        ┌──────────────┐
        │  内存(M)     │  ←  唯一的状态
        └──────┬───────┘
               │ 读
               ▼
   ┌─────────────────────────┐
   │  程序计数器(PC)         │
   └──────┬──────────────────┘
          │ 指示
          ▼
   ┌─────────────────────────┐
   │  指令:M[x] ← x + M[y]   │   ← 副作用
   └─────────────────────────┘
```

时间、状态、副作用三者不可分割。变量不是数学意义上的"变量",而是"装着某个值的内存盒子"。

### 1.1.2 函数式:模拟λ-演算

函数式编程的核心隐喻是**表达式与归约**。程序是一个表达式,执行就是化简它:

```
(fx) ──reduce──▶ (g h)
 (λx. x+x) 5    ──►  5+5  ──►  10
```

变量绑定一旦确立就不变,函数是一等公民,副作用被隔离在"effect system"或"monad"里。

### 1.1.3 表达力等价,但风格不同

Church 与 Turing 在 1936 年证明:**λ-可定义 = 图灵可计算**。两类语言在*计算能力*上等价,但在*表达被思考方式*上截然不同。

| 维度 | 命令式 | 函数式 |
|------|--------|--------|
| 基本对象 | 命令、状态 | 表达式、函数 |
| 时间 | 隐含在控制流 | 显式在数据结构(列表) |
| 并发 | 难(共享状态) | 自然(不可变) |
| 正确性 | 难以推理 | 易于推理(指称语义) |
| 主战场 | 系统编程 | 数据处理、编译器 |

## 1.2 九条核心宣言

本教程所有内容,可以归结为以下九条:

1. **纯函数就是函数**: `f: A → B`,相同输入总给出相同输出。
2. **不可变是默认**: 状态显式化为"新值"流(lineage),而不是"突变"。
3. **函数是值**: 高阶函数、柯里化、组合是基础操作。
4. **递归代替循环**: 经验上没有"循环"概念,迭代通过递归/折叠实现。
5. **类型即规约**: 类型不仅是分类,还是运行时不变量的证明。
6. **副作用隔离**: IO/State/Exception 全部通过代数接口(monad)描述。
7. **表达式 > 语句**: 一切皆值,一切可组合。
8. **律(law) > 实现**: Functor law / Monad law / ... 是评估实现正确性的基准。
9. **思考"做什么"而非"怎么做"**: 声明式风格,程序接近数学。

## 1.4 函数式编程不是什么

- **不是禁用 `for`/`while`**:你可以写 `forM_ [1..n] print`,只是它被定义为 list 上的 fold。
- **不是性能更慢**:GHC 编译出来的循环核心,经常与 C 同一量级甚至更快;真正的瓶颈在 thunk/closure,但都可以解除。
- **不是难以处理 IO**: Haskell 的 `IO` monad 已经让大型纯粹 FP 程序成为现实(cabal/Stack/Pandoc/XMonad 等)。
- **不是 Lisp**: Lisp 是 FP 的一种但不是全部;Haskell / ML / Clean 才是 FP 的"主流形态"。

## 1.5 立刻能看到的收益

| 性质 | 命令式 | 函数式 |
|------|--------|--------|
| 重构 | 牵一发动全身 | 纯函数独立 |
| 并发 | 锁/原子 | 不可变,无共享 |
| 测试 | 依赖 mock | 纯函数可完美测试 |
| 推导 | 不可能 | 等式推理 |
| 编译 | 弱类型运行时坑 | 类型即文档 |

## 1.6 思考题

1. 你所在团队的主要 bug 来源是什么?如果是"状态错误",FP 能在多大程度上消除?
2. 当你写 `let x = ...` 时,这里的 `x` 是"内存盒子"还是"数学变量"?界定你对"变量"的理解。
3. λ-演算与图灵机等价意味着什么?这对我们编译 FP 程序到 CPU 有什么启示?

## 1.7 小结

函数式编程是一组把"作为数学对象的函数"提升为头等公民、将副作用隔离为可被代数描述的接口,使得程序既可被推理又可被并行化的语言与编程范式。从 Ch2 起,我们会逐步建立它的数学基础,直到 Ch13 范畴论——这是理解所有高级抽象的钥匙。
