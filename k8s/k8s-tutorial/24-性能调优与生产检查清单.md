# 24. 性能调优与生产检查清单

## 24.1 性能调优的方法论

**性能调优 = 找瓶颈 → 测数据 → 改 → 再测**。

```text
1. 找到瓶颈
   - 是 CPU/内存/磁盘/网络?
   - 是应用层 / runtime / 调度层?
2. 量化
   - 测基线(改动前)
   - 设定目标
3. 改
   - 一次只改一项
4. 验证
   - 比较基线
5. 持续
   - 性能是渐变
```

**常见误区**:
- 没有测量就改 → 不知道改了什么
- 一次改多个 → 不知道哪个有效
- 改完不测 → 不知道效果
- 没有目标 → 改了也可能更差

## 24.3 K8s 组件调优

### 1. kube-apiserver

```yaml
# /etc/kubernetes/manifests/kube-apiserver.yaml
spec:
  containers:
  - command:
    - kube-apiserver
    - --max-requests-inflight=2000           # 2000 in-flight 读
    - --max-mutating-requests-inflight=1000  # 1000 in-flight 写
    - --request-timeout=60s
    - --watch-cache-sizes=node#1000,pod#5000,service#2000
    - --enable-priority-fairness=true         # K8s 1.22+ 限流
    - --api-audiences=api
    - --feature-gates=...
    - --v=2
    resources:
      requests: { cpu: 500m, memory: 1Gi }
      limits:   { cpu: 4, memory: 8Gi }
```

**关键参数**:
- `max-requests-inflight`:总 in-flight 请求数
- `max-mutating-requests-inflight`:写 in-flight
- `request-timeout`:请求超时
- `watch-cache-sizes`:watch 缓存
- `--enable-priority-fairness`:流控(防止某个用户打满)

### 2. etcd

```yaml
# /etc/etcd/etcd.config
data-dir: /var/lib/etcd
listen-client-urls: https://0.0.0.0:2379
advertise-client-urls: https://10.0.0.1:2379
# 关键
quota-backend-bytes: 8589934592      # 8GB
# 性能
heartbeat-interval: 100
election-timeout: 1000

# 启动参数
--quota-backend-bytes=8589934592
--max-request-bytes=10485760
```

**关键点**:
- SSD 磁盘(IOPS > 10k)
- `quota-backend-bytes`:etcd 存储上限
- 写多 = 瓶颈,需要分片

### 3. kube-scheduler

```yaml
# /etc/kubernetes/scheduler-config.yaml
apiVersion: kubescheduler.config.k8s.io/v1
kind: KubeSchedulerConfiguration
profiles:
- schedulerName: default-scheduler
  plugins:
    score:
      disabled:
      - name: NodeResourcesLeastAllocated    # 大集群关掉
```

**关键**:
- 减少 plugin 数量(关不用的)
- `percentageOfNodesToScore`:评估节点百分比(5-50%)

## 24.10 容量规划

### 公式

```text
总 CPU = 业务 CPU 总和 × 1.3(HA buffer) / 利用率(0.7)
总内存 = 业务内存总和 × 1.5
总磁盘 = 业务存储 × 1.5
节点数 = 总资源 / 单节点资源

示例:
  业务总: 50 核 / 200Gi
  集群总: 50 / 0.7 × 1.3 = 93 核
  单节点: 8C32G
  节点数: 93/8 = 12 节点
```

### 业务分级

```text
核心服务:   20% 资源,3 副本,跨 AZ
重要服务:   40% 资源,2 副本
普通服务:   30% 资源
批处理:    10% 资源,低优先级
```

## 24.12 成本优化

```text
1. 资源 requests 调准(用 VPA recommender)
2. 节点 Spot 实例(便宜 60-90%)
3. KEDA 缩到 0(无流量时缩容)
4. 镜像层去重(共享基础镜像)
5. 节点混部(Kata / gVisor 安全)
6. 不用资源直接删
7. 缩容测试场景资源
8. 用 Cluster Autoscaler 平衡
9. Karpenter Spot 混部
10. 监控成本(Kubecost)
```

helm install kubecost kubecost/cost-analyzer \

## 24.14 调优速查

| 瓶颈 | 调优方向 |
|------|----------|
| CPU 100% | 看应用火焰图 / 增加副本 / 调大 requests |
| 内存 OOM | 调大 limit / 修内存泄漏 |
| 磁盘慢 | 用 SSD / PV 改大 IOPS |
| 网络慢 | 用 Cilium eBPF / IPVS / jumbo frame |
| API Server 慢 | 调 max-requests / watch-cache / priority-fairness |
| etcd 慢 | SSD / 减 watch / 分片 |
| 调度慢 | 减少 plugin / 调 percentageOfNodesToScore |
| Pod 启动慢 | 优化镜像 / 预拉 / 减少 init container |
