## 33.6 50K 面试真题

### 基础题(必答)

**1. Pod 的生命周期?Pending → Running → Succeeded/Failed/Unknown**

**2. K8s 中 Service 的几种类型?**
- ClusterIP(默认,集群内)
- NodePort(节点端口)
- LoadBalancer(云 LB)
- ExternalName(CNAME)
- Headless(无 VIP,直连 Pod)

**3. Deployment 升级策略?**
- RollingUpdate(滚动,默认)
- Recreate(重建)

**4. 解释 Liveness、Readiness、Startup 探针区别**
- Liveness: 失败重启容器
- Readiness: 失败从 Endpoints 移除
- Startup: 启动慢时用,等通过才开始 liveness/readiness

**5. etcd 备份命令**
```bash

```

### 进阶题

**6. Pod 一直 Pending,如何排查?**
```text
1. kubectl describe pod → 看 Events
2. 常见原因:
   - 资源不够(CPU/内存)
   - 节点选择不匹配(nodeSelector/affinity)
   - 污点不容忍(taint/toleration)
   - PVC 未绑定
   - 镜像拉取慢
3. 排查命令:
   kubectl describe pod
   kubectl get events
   kubectl get nodes -o wide
```

**7. Service ClusterIP 无法访问,如何排查?**
```text
1. kubectl get svc -o wide  → 确认 ClusterIP
2. kubectl get endpoints <svc>  → 看是否有 Pod IP
3. 如果 endpoints 为空:
   - selector 不匹配
   - Pod 没 ready
   - readinessProbe 失败
4. 测连通性:
   kubectl run debug --rm -it --image=nicolaka/netshoot -- bash
   curl http://<cluster-ip>
```

**8. K8s 网络要求 / CNI 工作原理?**
```text
要求:
  - Pod IP 全集群唯一
  - Pod 不需要 NAT 可互通
  - 宿主机可不 NAT 访问 Pod
  - Pod 可访问外部

CNI:
  - kubelet 启动 Pod 前调 CNI 插件
  - CNI 创建 veth pair, 一端在 Pod,一端在网桥
  - 分配 IP,设路由
  - 主流: Calico/Cilium/Flannel
```

**9. StatefulSet 和 Deployment 区别?**
```text
StatefulSet:
  - 稳定网络标识(web-0, web-1...)
  - 稳定存储(每个 Pod 独立 PVC)
  - 顺序启停(0,1,2...;删除 N-1...0)
  - 适合: 数据库/消息队列/ZooKeeper

Deployment:
  - 随机名字 + ReplicaSet
  - 共享存储或无
  - 无序
  - 适合: 无状态 web
```

**10. HPA 公式?**
```text
desiredReplicas = ceil[currentReplicas * (currentMetricValue / desiredMetricValue)]

例:
  当前 3 副本, CPU 80%
  目标 50%
  期望 = ceil[3 * (80/50)] = ceil(4.8) = 5
```

### 高级题

**11. K8s 控制器模式 / Reconcile 循环**
```text
观察 spec(期望状态)
  ↓
对比 status(实际状态)
  ↓
差异 → 行动(create/update/delete)
  ↓
watch spec/status 变化 → 重新开始

例: Deployment 控制器
  - 观察 spec.replicas
  - 对比 status.replicas
  - 差异: 创建/删除 Pod
  - 监听 Pod 变化(创建/删除/状态)
```

**12. OPA / Kyverno 如何拒绝 latest 标签?**
```yaml
# Kyverno
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata: { name: no-latest }
spec:
  validationFailureAction: Enforce
  rules:
  - name: deny-latest
    match:
      any: [{resources: {kinds: ["Pod"]}}]
    validate:
      message: "禁止 latest 标签"
      pattern:
        spec:
          containers:
          - image: "!*:latest"
```

**13. 镜像签名验证流程?**
```text
1. CI 用 cosign 签名镜像
2. 镜像推 registry
3. K8s admission(Kyverno/Connaisseur):
   - 拉镜像元数据
   - 验签(公钥/Rekor 查询)
   - 失败 → 拒绝 Pod 创建
```

**14. etcd 集群为什么推荐 3 或 5 节点?**
```text
Raft 共识要求多数派:
  - 3 节点: 容忍 1 故障 (2/3)
  - 5 节点: 容忍 2 故障 (3/5)
  - 7 节点: 容忍 3 故障 (4/7)

为什么不是更多:
  - 性能: write 要同步到多数派,节点多慢
  - 脑裂: 半数失联 = 集群不可用
  - 实用: 3 或 5 足够
```

**15. Pod 之间的网络流量如何加密?**
```text
方法:
  1. Service Mesh(Istio mTLS): 自动
  2. NetworkPolicy: 限流量,不加密
  3. 应用层 TLS
  4. WireGuard(Cilium 加密模式)
  5. IPsec
```

**16. 集群升级策略?**
```text
控制面:
  1. 升级 kubeadm/kubelet/kubectl
  2. kubeadm upgrade plan
  3. kubeadm upgrade apply v1.31.0
  4. 排空 + 升级第一个 master
  5. 升级其他 master
  6. 升级 worker(可滚动)

数据面:
  - kubectl drain node  → 升级 → uncordon
  - 用 Cluster API 自动
  - 用 ArgoCD 同步
```

**19. 镜像拉取策略(Always/IfNotPresent/Never)**
```text
Always:
  - 每次都拉(慢,准)
  - 用 :latest 必须
  - 生产 tag 固定也建议

IfNotPresent:
  - 本地有就跳过(快)
  - tag 固定推荐

Never:
  - 只用本地
  - 离线环境/CI 注入
```

**20. Sidecar 容器 vs Init 容器?**
```text
Init Container:
  - 顺序执行
  - 在主容器前完成
  - 退出码 0 才继续
  - 用途: 初始化/等待依赖

Sidecar:
  - 与主容器并行运行
  - 共享网络/存储
  - 整个 Pod 生命周期
  - 用途: 日志采集/代理/监控
```

**21. eBPF 在 K8s 中的应用?**
```text
CNI:
  - Cilium 用 eBPF 替代 iptables
  - 性能更好,支持 L7 策略

可观测:
  - Pixie 零代码应用可观测
  - Hubble 网络流
  - Inspektor Gadget

安全:
  - Tetragon 运行时检测
  - Falco + eBPF driver

优势:
  - 延迟低(< 0.1ms)
  - 零侵入(不改应用)
  - 内核级可见
```

**22. 如何保证 K8s 部署零停机?**
```text
1. 多副本 + 滚动升级
2. readinessProbe 必设
3. 配 PodDisruptionBudget
4. 优雅关闭: preStop hook
5. terminationGracePeriodSeconds 足够
6. 数据库迁移用 expand-contract
7. 流量切走后再停
```

**23. 集群从 100 扩到 1000 节点,主要挑战?**
```text
1. etcd 性能(分片或专用 etcd)
2. apiserver 限流
3. 控制器性能
4. 网络规模(CNI 路由条目)
5. DNS 解析(CoreDNS 撑不住 → NodeLocal DNSCache)
6. 镜像分发(镜像多 → 拉慢 → Dragonfly)
7. 监控存储(Thanos/Cortex)
8. 证书轮换
```

**24. Pod 中两个容器共享什么?**
```text
共享:
  - 网络命名空间(同一 IP)
  - 存储卷
  - 生命周期(一起启停)
  
不共享:
  - 进程命名空间(默认)
  - 用户命名空间(默认)
  - IPC/PID 需要显式 share
```

**25. 解释 kube-proxy 三种模式**
```text
userspace:
  - K8s 1.0 早期模式
  - 慢,已废弃

iptables:
  - 默认
  - 用 iptables 规则 DNAT
  - 规则多时性能差

IPVS:
  - 基于 netlink
  - 更快,支持多种负载均衡算法
  - 大集群推荐
```

**28. 数据库要不要上 K8s?**
```text
场景判断:
上 K8s:
  - 简单应用(单实例 Redis/Cache)
  - Operator 成熟(PostgreSQL/MySQL/Kafka)
  - 弹性伸缩需求

不上 K8s:
  - 强一致要求(RDS/PolarDB 更稳)
  - 团队 K8s 经验不足
  - 合规要求(数据驻留)

生产铁律:
  - 数据库主从切换用 Operator
  - 备份异地
  - 监控完善
  - 应急 Runbook
```

**29. CI/CD 流水线如何设计?**
```text
Git → PR → CI:
  1. lint
  2. 单元测试
  3. 镜像构建(kaniko/buildah)
  4. 镜像扫描(Trivy)
  5. cosign 签名
  6. 推到 registry
  
Merge → CD:
  1. ArgoCD 监到 Git 变化
  2. 同步 dev 环境
  3. 跑 smoke test
  4. 自动同步 staging
  5. 测试通过 → 手动同步 prod
  6. Argo Rollouts 渐进式 + 监控
  7. 自动回滚(指标失败)
```
