# 01. 核心概念与架构

## 1.1 Helm 是什么

**Helm 是 Kubernetes 的包管理工具**,相当于 Kubernetes 生态的 `apt/yum/homebrew`。它把一组相关的 Kubernetes 资源打成一个 **Chart**(包),用 **values** 进行参数化,让一份 Chart 能在不同环境/不同配置下重复部署。

### 解决什么问题

没有 Helm 之前:
- 部署一个完整应用(Deployment + Service + ConfigMap + Ingress + Secret...),要写 5 个 yaml
- 改一个镜像版本要改 5 个文件并保持一致
- 不同环境(prod / staging / dev)要维护 3 套几乎一样的 yaml
- 回滚?手动 `kubectl apply` 旧版本,容易出错
- 多人协作?靠复制粘贴和人工 review

有了 Helm:
- 一份 Chart + 多个 values 文件 → 多个环境
- `helm upgrade` 即可升级,自动 diff
- `helm rollback` 一键回滚
- `helm history` 看到每次变更
- 模板 + values 把"代码"和"配置"分离

## 1.2 Helm 3 vs Helm 2 关键差异

| 特性 | Helm 2 | Helm 3 |
|------|--------|--------|
| 架构 | Client + Tiller(集群内) | 仅 Client |
| 权限 | Tiller 需 cluster-admin | 默认使用 kubeconfig |
| Release 存储 | ConfigMap | Secret(命名空间隔离更好) |
| Chart apiVersion | 仅 v1 | v1 / v2(支持依赖等) |
| 依赖 | requirements.yaml | Chart.yaml dependencies |
| 三方稳定性 | 需 `crd-install` hook | 内置 CRD 字段 |
| 库 Chart | 不支持 | 支持 `type: library` |
| 入口命令 | `helm init` | 无需 init |

**当前必须用 Helm 3**(3.8+ 推荐,3.14+ 是当前稳定版)。本教程全部基于 Helm 3。

## 1.3 四大核心概念

### Chart(包)
Helm 的"软件包"。一个目录,里面包含模板 + 默认配置 + 元数据。Chart 可以发布到 Repository。

```text
my-app/
├── Chart.yaml          # 元数据
├── values.yaml         # 默认配置
├── templates/          # Kubernetes 资源模板
│   ├── deployment.yaml
│   ├── service.yaml
│   └── ingress.yaml
└── charts/             # 依赖的子 chart
```

### Release(实例)
Chart 在某个集群上的"一次部署"。同一个 Chart 可以用不同的 values 部署成多个 Release。

```bash
helm install web-release bitnami/nginx          # 第一个实例
helm install api-release bitnami/nginx --set service.port=8080  # 第二个实例
```

### Repository(仓库)
存放 Chart 的 HTTP 服务器,类似 Docker Registry。常用仓库:
- [Artifact Hub](https://artifacthub.io/) (官方聚合)
- `https://charts.bitnami.com/bitnami`
- `https://kubernetes.github.io/ingress-nginx`
- OCI: `oci://registry-1.docker.io/yourorg`

### Revision(版本号)
每次 `helm install / upgrade / rollback` 都会产生一个新的 Revision。Release 是一组 Revision 的历史记录。

```bash
$ helm history web-release
REVISION  UPDATED                   STATUS      CHART           APP VERSION  DESCRIPTION
1         2024-01-01 10:00:00      superseded  nginx-13.2.0    1.25.1       Install complete
2         2024-01-15 14:30:00      deployed    nginx-13.2.1    1.25.2       Upgrade complete
3         2024-02-01 09:00:00      failed      nginx-13.3.0    1.25.3       Upgrade failed
```

## 1.4 Helm 架构

```mermaid
┌─────────────────┐
│   helm CLI      │ ← 你执行命令
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  Helm Go SDK    │ ← 解析 Chart / 渲染模板 / 计算 diff
└────────┬────────┘
         │
         ├─→ Chart Repo (HTTP/OCI)
         ├─→ 本地 Chart 目录
         └─→ Kubernetes API Server
                  │
                  ▼
         ┌─────────────────┐
         │ Secrets         │ ← Release 状态以 Secret 存储
         │ (命名空间隔离)  │
         └─────────────────┘
```

**关键点**:
- Helm 3 没有 Tiller,直接和 kube-apiserver 通信,使用你 `~/.kube/config` 的身份
- Release 信息以 Secret 存在 release 所在命名空间(`sh.helm.release.v1.<release-name>.<revision>`)
- 卸载时这些 Secret 也会被清理(可保留 `--keep-history`)

## 1.5 第一个 Chart:10 秒体验

```bash
# 安装 helm(以 macOS 为例)
brew install helm

# 验证
helm version
# version.BuildInfo{Version:"v3.14.0", GitCommit:"...", GitTreeState:"clean", GoVersion:"go1.21.6"}

# 添加仓库
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update

# 安装 nginx
helm install my-nginx bitnami/nginx

# 查看
helm list
helm status my-nginx

# 自定义 values 升级
helm upgrade my-nginx bitnami/nginx --set service.type=LoadBalancer

# 回滚
helm history my-nginx
helm rollback my-nginx 1

# 卸载
helm uninstall my-nginx
```

## 1.6 专家级理解:Chart 是一段 Go 模板

Helm 模板引擎是 [Sprig](https://masterminds.github.io/sprig/) + Go template。理解这一点很关键:

- `{{ .Values.image.tag }}` 是变量插值
- `{{ include "mychart.labels" . }}` 是函数调用
- 所有渲染都在客户端完成,k8s 收到的是"已经替换好"的 yaml

这意味着:
1. **任何 Go template 写法都适用**(语法细节见 04 模板篇)
2. **chart 渲染是确定性的**——给定相同的 chart + values,输出永远一致(适合 GitOps)
3. **可以在本地用 `helm template` 完全离线验证**,无需集群

## 1.7 本章小结

- Helm = Kubernetes 的包管理工具,核心是 Chart(模板+默认配置)+ Release(运行时实例)
- Helm 3 移除了 Tiller,直接与 apiserver 通信
- 四大概念:Chart / Release / Repository / Revision
- 模板引擎 = Go template + Sprig,纯客户端渲染
