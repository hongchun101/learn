# 10. 生产最佳实践与安全

## 10.1 Release 命名规范

| 命名模式 | 适用 |
|----------|------|
| `<env>-<app>` | 推荐:`prod-myapp`、`staging-myapp` |
| `<app>-<env>` | 也常见:`myapp-prod` |
| `<tenant>-<app>-<env>` | 多租户:`acme-web-prod` |

**不要用**:
- `latest`(语义不清)
- 全大写(K8s 资源要求小写)
- 超过 53 字符(部分资源名限制)

## 10.2 命名空间管理

```bash
# 1. 显式指定命名空间,避免用 default
helm install myapp ./chart -n my-namespace --create-namespace

# 2. 用 --create-namespace 自动创建
helm upgrade myapp ./chart -n my-namespace

# 3. CI 中强制 namespace
helm upgrade myapp ./chart \
  -n $(yq .env.NS values.yaml) \
  --create-namespace
```

**避免一个 release 跨命名空间**:Helm 设计上每个 release 属于一个 namespace。

## 10.3 Secret 管理(关键!)

### 反模式:明文 values

```yaml
# ❌ 绝对不要这样做
secrets:
  dbPassword: "my-secret-password"
```

### 方案 1:Helm Secrets + SOPS

```bash
# 1. 安装 helm-secrets 插件
helm plugin install https://github.com/jkroepke/helm-secrets

# 2. 用 SOPS 加密 values
sops --encrypt --age <public-key> values-prod.yaml > values-prod.enc.yaml

# 3. 安装时解密
helm secrets install myapp ./chart -f values-prod.enc.yaml
```

### 方案 2:External Secrets Operator

```yaml
# 由 ExternalSecret 从 Vault/AWS SM 同步到 K8s Secret
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: db-credentials
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: vault-backend
    kind: ClusterSecretStore
  target:
    name: db-credentials
  data:
    - secretKey: password
      remoteRef:
        key: secret/data/db
        property: password
```

### 方案 3:Sealed Secrets

```bash
# 1. 安装 controller
kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.24.0/controller.yaml

# 2. 加密
kubeseal --format yaml < secret.yaml > sealed-secret.yaml

# 3. 部署 sealed-secret.yaml,K8s 端自动解密
```

### 方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| SOPS | 文件级加密,GitOps 友好 | 密钥管理需要 age/pgp |
| External Secrets | 运行时拉取,密钥不落盘 | 需要 Vault 等后端 |
| Sealed Secrets | 简单,集群本地加密 | 集群 controller 单点 |
| 阿里云/AWS KMS + 插件 | 与云集成 | 厂商绑定 |

## 10.4 资源限制

**每个** deployment 都必须设 resources:

```yaml
# values.yaml
resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 500m
    memory: 512Mi
```

**生产配置建议**:
- `requests` = 稳定负载的 70-80%
- `limits` = requests 的 1.5-2x
- memory 必须设 limit(OOM 难调试)
- CPU 可不设 limit(避免 throttling 影响 latency)

## 10.5 HPA + PDB

### HPA(自动扩缩容)

```yaml
autoscaling:
  enabled: true
  minReplicas: 3
  maxReplicas: 20
  targetCPUUtilizationPercentage: 70
  targetMemoryUtilizationPercentage: 80
```

**生产建议**:
- 至少 3 个副本避免单点
- maxReplicas 不要设太大(数据库撑不住)
- 用 behavior 字段控制扩缩速度

```yaml
behavior:
  scaleUp:
    stabilizationWindowSeconds: 30
    policies:
      - type: Percent
        value: 100
        periodSeconds: 30
  scaleDown:
    stabilizationWindowSeconds: 300
    policies:
      - type: Percent
        value: 10
        periodSeconds: 60
```

### PDB(Pod Disruption Budget)

```yaml
podDisruptionBudget:
  enabled: true
  minAvailable: 2  # 或 "50%"
  # maxUnavailable: 1  # 二选一
```

**为什么需要**:`kubectl drain` 时,k8s 会强制驱逐,可能导致 0 副本。PDB 限制最少可用数。

## 10.6 镜像 tag 策略

| 策略 | 适用 |
|------|------|
| `latest` | ❌ **绝对禁止** |
| 固定版本 `1.2.3` | ✅ 稳定服务 |
| SemVer `~1.2.3` | ⚠️ 仅在 CI 自动更新时 |
| 镜像 digest `sha256:abc...` | ✅✅ 最稳定 |
| Git SHA `git-abc123` | ✅ 内部应用 |

```yaml
# 推荐
image:
  repository: myorg/myapp
  tag: "1.2.3"
  digest: "sha256:abc123..."  # 比 tag 更精确
```

```yaml
# values-prod.yaml
image:
  tag: "1.2.3"
  digest: "sha256:abc123..."
```

## 10.7 自动滚动升级

用 ConfigMap/Secret 变更触发 Pod 重建:

```yaml
# templates/deployment.yaml
spec:
  template:
    metadata:
      annotations:
        # checksum 变了 = configmap 变了 = 触发滚动升级
        checksum/config: {{ include (print $.Template.BasePath "/configmap.yaml") . | sha256sum }}
        checksum/secret: {{ include (print $.Template.BasePath "/secret.yaml") . | sha256sum }}
```

**更优雅的方案**:用 [Reloader](https://github.com/stakater/Reloader) 自动检测变更。

## 10.9 ServiceAccount 与 RBAC

```yaml
serviceAccount:
  create: true
  annotations:
    # IRSA(AWS)/ Workload Identity(GCP)
    eks.amazonaws.com/role-arn: arn:aws:iam::123:role/myapp
  automountServiceAccountToken: false  # 不用时关掉
```

```yaml
# 细粒度 RBAC
rbac:
  create: true
  rules:
    - apiGroups: [""]
      resources: ["configmaps", "secrets"]
      verbs: ["get", "list"]
    - apiGroups: ["apps"]
      resources: ["deployments"]
      verbs: ["get", "list", "watch"]
```

**永远不要给 default service account 权限**。

## 10.10 网络策略

```yaml
networkPolicy:
  enabled: true

    - from:
        - podSelector:
            matchLabels:
              app: ingress-nginx

        - port: 8080

    - to:
        - podSelector:
```

**默认拒绝一切,然后白名单**。

## 10.11 Chart 签名与验证

```bash
# 1. 用 GPG 签名 chart
helm package --sign --key 'My Key' --keyring ~/.gnupg/secring.gpg ./mychart

# 2. 推送到仓库
helm push myapp-1.0.0.tgz oci://registry

# 3. 验证
helm install myapp oci://registry/myorg/myapp --verify
```

**配合 cosign / Notary 做更现代的供应链签名**。

## 10.13 健康检查必填

```yaml
livenessProbe:
  httpGet:
    path: /healthz
    port: http
  initialDelaySeconds: 30
  periodSeconds: 10
  timeoutSeconds: 3
  failureThreshold: 3

readinessProbe:
  httpGet:
    path: /readyz
    port: http
  initialDelaySeconds: 5
  periodSeconds: 5

startupProbe:  # 给慢启动应用更多时间
  httpGet:
    path: /healthz
    port: http
  failureThreshold: 30
  periodSeconds: 10
```

**注意**:
- `/healthz` 必须是"深度健康检查",依赖关键服务
- 避免 `/healthz` 也查 DB(造成级联失败)
- 用 `/readyz` 控制流量

## 10.14 优雅关闭

```yaml
spec:
  template:
    spec:
      terminationGracePeriodSeconds: 60
      containers:
        - name: app
          lifecycle:
            preStop:
              exec:
                command: ["/bin/sh", "-c", "sleep 5 && kill -SIGTERM 1"]
```

```yaml
# Service 也要设
service:
  annotations:
    # 等 readiness 失败才从 endpoints 移除
    service.beta.kubernetes.io/healthcheck-grace-period-seconds: "30"
```

**生产必填**:preStop 留出时间让 readiness 失败 → 流量摘除 → 真正停止。

## 10.15 审计与合规

```bash
# 1. 锁定 release 历史
helm history myapp -n my-ns --max 50

# 2. 导出当前状态
helm get manifest myapp -n my-ns > manifest.yaml

# 3. 渲染对比
helm diff upgrade myapp ./chart -f values.yaml

# 需要 helm-diff 插件
helm plugin install https://github.com/databus23/helm-diff
```

```bash
# 强烈建议:CI/CD 必经
helm diff upgrade myapp ./chart -f values-prod.yaml | tee diff.log
# 仅在 diff 可控时才允许继续
```

## 10.16 本章小结

- 命名空间 + Release 命名是基础
- Secret 永远不要明文,用 SOPS / External Secrets / Sealed Secrets
- 资源限制 + HPA + PDB 是稳定性三件套
- 镜像 tag 固定,digest 最稳
- 滚动升级用 checksum annotation 自动触发
- securityContext + NetworkPolicy 收紧权限
- CI 必经 `helm diff` review
