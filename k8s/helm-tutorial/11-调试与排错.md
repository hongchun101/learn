# 11. 调试与排错

## 11.1 调试三件套

```bash
# 1. 渲染到 stdout(不连接集群)
helm template myrelease ./mychart

# 2. 验证 yaml 语法 + 模拟服务器端校验
helm template myrelease ./mychart --validate

# 3. 静态检查
helm lint ./mychart
helm lint ./mychart --strict
```

## 11.2 必装插件:helm-diff

```bash
helm plugin install https://github.com/databus23/helm-diff

# 看 upgrade 实际改动
helm diff upgrade myapp ./chart -f values-prod.yaml

# 模拟 install
helm diff install myapp ./chart -f values-prod.yaml
```

**生产规范**:CI/CD 必经 helm diff,人工 review 后再 apply。

## 11.3 必装插件:helm-unittest

```bash
helm plugin install https://github.com/helm-unittest/helm-unittest

# 写测试
cat > templates/deployment_test.yaml <<'EOF'
suite: test deployment
templates:
  - deployment.yaml
release:
  name: myapp
  namespace: default
values:
  - ../values.yaml
tests:
  - it: should set replicas correctly
    asserts:
      - equal:
          path: spec.replicas
          value: 2
  - it: should set image
    asserts:
      - equal:
          path: spec.template.spec.containers[0].image
          value: "nginx:1.25.0"
EOF

helm unittest ./mychart
```

## 11.4 常见错误速查

### 1. `function "X" not defined`

```text
Error: template: mychart/templates/cm.yaml:5:12: executing "mychart/templates/cm.yaml" at <include "mychart.foo">:
error calling include: template: no template "mychart.foo" associated with template "mychart"
```

**原因**:找不到命名模板。

**解决**:
- 检查 `define "mychart.foo"` 拼写
- 检查文件是不是 `_helpers.tpl` 且加了 `{{/* */}}` 包错地方
- 确认文件名匹配

### 2. `can't evaluate field X in type interface {}`

```text
error calling include: template: ... at <.Values.foo.bar>:
can't evaluate field bar in type interface {}
```

**原因**:`.Values.foo` 是 nil,或不是 map。

**解决**:
```bash
# 先看渲染结果
helm template myapp ./chart --show-only templates/cm.yaml
# 看看 Values.foo 实际是什么
helm template myapp ./chart -f values.yaml --debug | grep -i "values"
```

### 3. 渲染出 `<no value>`

```yaml
data:
  key: {{ .Values.config.key }}  # config.key 不存在
```

输出:
```yaml
data:
  key: <no value>
```

**解决**:
```yaml
data:
  key: {{ .Values.config.key | default "" | quote }}
```

或提前判断:
```yaml
{{- if hasKey .Values.config "key" }}
data:
  key: {{ .Values.config.key | quote }}
{{- end }}
```

### 4. 缩进乱了

```yaml
# ❌ 错的:toYaml 后 indent 4,但实际数据有 3 层嵌套
spec:
  {{- toYaml .Values.config | indent 4 }}
# 输出:
# spec:
#       foo:  # 缩进爆了
#         bar: baz
```

**解决**:
```yaml
spec:
  {{- toYaml .Values.config | nindent 4 }}
# nindent = "\n" + indent,每行缩进 4
```

或正确计算缩进:
```yaml
data:
  {{- range $k, $v := .Values.config }}
  {{ $k }}: {{ $v | quote }}
  {{- end }}
```

### 5. hook 失败导致 release failed

```text
Error: UPGRADE FAILED: pre-upgrade hooks failed: job failed: BackoffLimitExceeded
```

**解决**:
```bash
# 1. 看 hook job 状态
kubectl get job -n my-ns -l "helm.sh/hook"
kubectl describe job <name> -n my-ns
kubectl logs <pod> -n my-ns

# 2. 修复后重新升级
helm upgrade myapp ./chart
# 或
helm upgrade myapp ./chart --no-hooks
```

### 6. CRD 字段被拒绝

```text
Error: UPGRADE FAILED: error validating "...": ValidationError(Pod.spec.containers[0]): unknown field "xxx"
```

**原因**:用了不存在的字段。

**解决**:
- 检查 k8s 版本是否支持该字段
- 检查 CRD 是否已安装
- `helm template --validate` 提前发现

### 7. 资源配额超出

```text
Error: failed to create resource: ... exceeded quota: ...
```

**解决**:
- 减小 requests/limits
- 申请更大 namespace quota
- 检查 ResourceQuota

### 8. 镜像拉取失败

```text
ImagePullBackOff: Back-off pulling image "myorg/myapp:latest"
```

**原因**:`latest` 标签 / 未登录 / digest 错。

**解决**:
```bash
# 测试拉取
docker pull myorg/myapp:1.2.3

# 检查 imagePullSecrets
kubectl get sa myapp -o yaml
```

### 9. values 必需字段缺失

```text
Error: required: image.repository is required
```

**解决**:用户必须设该字段,或提供默认值。

## 11.5 调试技巧汇总

### 临时打印

```yaml
# 在模板中临时加
{{- $debug := printf "values: %+v" .Values -}}
{{- $debug | quote }}
```

或:
```yaml
# 创建一个 debug configmap
{{- if eq (default "" .Values.debug) "true" }}
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ include "mychart.fullname" . }}-debug
data:
  values: {{ .Values | toJson | quote }}
  chart: {{ .Chart | toJson | quote }}
  release: {{ .Release | toJson | quote }}
{{- end }}
```

```bash
helm install myapp ./chart --set debug=true
kubectl get cm myapp-debug -o yaml
```

### 渲染指定文件

```bash
helm template myapp ./chart --show-only templates/deployment.yaml
```

### 对比两次渲染

```bash
helm template myapp ./chart -f values.yaml > before.yaml
helm template myapp ./chart -f values-new.yaml > after.yaml
diff -u before.yaml after.yaml
```

### 单步调试

```bash
# 用 kubectl 校验 chart 渲染结果
helm template myapp ./chart > manifest.yaml
kubectl apply --dry-run=server -f manifest.yaml
```

## 11.6 性能与超大 Chart

100+ 模板的 chart 渲染慢?优化:

1. **拆分**:用 helmfile 而非 umbrella chart
2. **缓存依赖**:`helm dependency build` 而不是 `update`
3. **并行渲染**:Helm 内部已支持多模板并行,无需手动
4. **避免 lookup**:lookup 是同步 apiserver,慢
5. **简化模板**:嵌套太深的 range 会拖慢

## 11.7 排错 Checklist

```text
□ helm template 能渲染成功吗?
□ helm lint 有警告吗?
□ helm diff upgrade 改动合理吗?
□ kubectl apply --dry-run=server 校验通过吗?
□ 镜像能拉取吗?(imagePullSecrets)
□ RBAC 权限足够吗?
□ 资源配额够吗?
□ 健康检查路径存在吗?
□ Service selector 匹配 Pod labels 吗?
□ ConfigMap/Secret 名和挂载路径对吗?
□ PDB 是否过严导致 drain 失败?
```

## 11.10 本章小结

- 调试顺序:`lint` → `template` → `template --validate` → `install --dry-run` → `diff upgrade` → `apply`
- 必装插件:`helm-diff`、`helm-unittest`
- 常见 8 大错误都有标准排错路径
- 大型 chart 性能优化:拆 + 减少 lookup
- 用 `pluto`、`polaris` 长期监控
